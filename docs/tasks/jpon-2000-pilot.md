# 住所でポン！2000年版 苗字集計パイロット

## 目的

有料版の2000年電話帳を名字の基準年に使えるか、認証、地域列挙、苗字表の整合性、
再開可能な保存を100町域で検証した。実行日は2026年8月15日。

## 取得方法

- 認証済みの年度トップから都道府県、市区町村、町域の順に通常HTMLリンクを列挙
- PDF、XLS、CSVは取得しない
- 同時実行1。各レスポンスを完全に受信・解析し、SQLiteへ保存してから2秒待機
- ChromeのJpon Cookieは起動時に非公開パイプでメモリへ受け渡し、ファイル、ログ、DBへ
  保存しない
- HTML、個人名、電話番号、住所は保存せず、町域URL、完了日時、苗字別ローカル軒数だけを
  年度専用SQLiteへ保存
- 403で停止し、429・5xxは`Retry-After`と指数バックオフに従う
- 「多い苗字」と「希少苗字」の軒数を和集合し、重複は軒数一致を要求して1回だけ計上

実行コマンド:

```sh
python tools/pilot_jpon_2012_surnames.py \
  --year 2000 --limit 100 --delay 2 --jitter 0 \
  --db /home/jiro/.local/share/jpon-2000-census/jpon-2000.sqlite3 \
  --output /home/jiro/.local/share/jpon-2000-census/jpon-2000-summary.csv \
  --user-agent 'soramimic-wordlists-jpon-2000-census/0.1 (+https://github.com/soramimic/soramimic-wordlists)'
```

## 判定

2000年版でも、個人明細を保存せず町域別苗字軒数だけを全国集計できる。認証Cookieの
メモリ内利用、年度別DB、2秒待機、途中再開も実環境で動作した。

最初の100町域はキュー順に北海道内を処理した地域偏りのある標本であり、この集計値を
全国順位には使わない。同じDBで全国取得を継続し、全町域の列挙完了、未取得URL 0件、
表間矛盾0件を確認してから順位を確定する。

## 連続運転でのレート見直し

100町域の試行後も同じ2秒待機で継続したところ、累計119町域を保存した次のリクエストで
HTTP 403となり、収集器は設計どおり直ちに停止した。2秒待機は短い試行では問題がなくても
長期連続運転には速すぎると判断する。アクセス規制を回避せず十分に冷却した後、既存DBから
受信完了後10秒待機で再開する。403時は自動再起動しない。

# 住所でポン！2012年版 苗字集計パイロット

## 目的

SudachiDictを名字の母集団にせず、電話帳そのものを母集団として全町域から苗字別軒数を
集計できるか、100町域で検証した。実行日は2026年8月15日。

## 取得方法

- 対象: `sitemap-2012-0.xml` の先頭100町域
- ページ分割URLは町域単位に正規化し、`p=1`だけを取得
- 同時実行1。パーサー確認用の最初の5町域は2秒間隔、その後95町域は
  基本間隔10秒、±20%の揺らぎ
- User-AgentにリポジトリURLとパイロット用途を記載
- 403で即時停止、429・5xxは待機して再試行
- HTML・個人名・電話番号・住所は保存せず、町域URL、完了日時、苗字別ローカル軒数だけを
  `tools/.cache/jpon-2012-pilot-v2.sqlite3` に保存
- 「多い苗字」「希少苗字」のローカル軒数を苗字で和集合し、重複は1回だけ計上

実行コマンド:

```sh
python tools/pilot_jpon_2012_surnames.py \
  --limit 100 --delay 10 --jitter 0.2 \
  --db tools/.cache/jpon-2012-pilot-v2.sqlite3 \
  --output tools/.cache/jpon-2012-pilot-v2.csv \
  --user-agent 'soramimic-wordlists-jpon-feasibility-pilot/0.1 (+https://github.com/soramimic/soramimic-wordlists)'
```

## 結果

| 指標 | 結果 |
|---|---:|
| 完了町域 | 100 |
| 電話帳の掲載総件数 | 7,741 |
| 抽出した苗字軒数 | 6,263 |
| 掲載件数に対する苗字軒数 | 80.9% |
| 異なる苗字 | 685 |
| 苗字0件の町域 | 14 |
| ページ分割された町域 | 27 |
| 1町域の最大掲載件数 | 814 |
| 1町域から得た最大異なり苗字数 | 94 |
| 2種類の表で重複した町域・苗字 | 1,185 |
| 重複部分の軒数矛盾 | 0 |
| HTTP 403・429 | 0 |
| HTML構造エラー | 0 |

掲載件数と苗字軒数の差には法人・店舗等が含まれる。苗字0件の町域も正常に処理できた。
同じ町域の`p=1`と`p=2`を別途比較したところ、13姓・合計100軒が完全一致したため、
ページ分割を全取得すると二重計上になることも確認した。

## 判定

電話帳を正とする苗字集計は技術的に可能である。個人明細を保存したり独自に姓名分割したり
せず、サイトが公開する町域別苗字軒数だけで全国集計できる。

ただし、この100町域は同一サイトマップ断片の先頭で地域的に偏るため、ここで得た順位は
全国順位として利用しない。全国版では約30万町域を取得し、全町域の軒数を合計してから
順位を確定する。10秒間隔なら概算35日前後を要する。

収集器は `--all-shards` で全30断片を一度だけ読み込み、町域URLキューをSQLiteへ
永続化できる。以後は同じコマンドを再実行すれば、取得済み町域を飛ばして続行する。
全国取得を開始する場合は、Git管理外の同じDBを指定して次のように実行する。

```sh
python tools/pilot_jpon_2012_surnames.py \
  --all-shards --limit 300000 --delay 10 --jitter 0.2 \
  --db tools/.cache/jpon-2012-full.sqlite3 \
  --output tools/.cache/jpon-2012-full.csv \
  --user-agent 'soramimic-wordlists-jpon-census/0.1 (+https://github.com/soramimic/soramimic-wordlists)'
```

全件完了後、都道府県をまたぐ標本検査、表の矛盾0件、未取得URL 0件を確認してから
`myoji.csv` の母集団・順位へ反映する。

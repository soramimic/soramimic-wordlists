# ADR 00020: baseball/football の実写が無い行にチームカラーの選手カードを割り当てる

- Status: accepted
- Date: 2026-07-28
- Supersedes: none
- Superseded by: none

## Context

baseball.csv は28,606行中10,632行(37%)、football.csv は19,760行中1,860行(9%)にしか
画像が無かった。ソラミミ動画は単語ごとに1枚絵を出すので、画像が無い行は他のリストと
同じ見せ方ができない。他のリストは既に「実写が無い行を生成画像で埋める」形になっている
(pokemon の型色カード ADR 00002、sekitsui/plant の分類イメージ、youtuber の象徴カード
ADR 00018)。選手リストだけが空欄のまま残っていた。

実写が増えないのは構造的な理由による。自由ライセンスの人物写真は Wikimedia Commons に
あるものだけで、歴代選手・下部リーグの選手にはほぼ無い。球団・クラブが公開している
選手写真は本人と球団の権利物で、引用の要件も満たさない。つまり**残りを実写で埋める道は無い**。

一方、選手カードには youtuber には無い材料がある。両CSVとも `team` 列を持っていて
(baseball は元から、football は ADR 00016 で追加)、**チームカラーは公表された事実**である。
色そのものは著作権の保護対象ではない(アイデア・事実の領域)ので、
「阪神のチームカラーは黄と黒」という情報を配色に使うことと、ロゴやユニフォームを複製する
ことは別物として扱える。

## Decision

### 1. 実写が無い人にだけ、配色と文字と自作図形だけのカードを作る

`tools/gen_player_cards.py`。youtuber の象徴カード(ADR 00018)と同じ考え方で、素材を
一切借りない。

- **1人1枚**。同じ人物の full/family/given 行は同じ `original` なので1枚を共有する。
  行数(28,606 + 19,760)ではなく人数(6,082 + 6,505)ぶんしか作らない
- **実写がある人のカードは作らない**。作ると使われないSVGが数千枚リポジトリに残る
- ファイル名は名前から決定的に導く `bb_<sha1(original)の先頭10桁>.svg` /
  `fb_...`。id は将来の再採番に耐えないので使わない
- 実写のある行は**絶対に触らない**。冪等で、2回目以降の実行はCSVを書き換えない

### 2. チームカラーは「テキストで書かれた色」だけを出典にする

`tools/fetch_team_colors.py` が集めて `tools/team_colors.json` に**出典URL付き**で持つ
(`tools/nations_map.csv` / `tools/youtuber_colors.json` と同じ「tools配下の対応表」の慣習)。

- **football**: ja.wikipedia のクラブ記事インフォボックスの
  `| カラー = {{color box|#B8193F}} ディープレッド`。Jリーグ公式のクラブガイドを出典に持つ
- **baseball**: en.wikipedia の球団記事インフォボックスの `| colors = ... {{color box|#ed9e21}}`。
  ja.wikipedia の野球チームinfoboxには色の項目が無いため
- 取得するのは**ウィキテキストだけ**。ロゴ・エンブレム・ユニフォーム画像はダウンロードも
  参照もしない
- hex が無く色名しか書かれていない記事は、基本色名 → 代表色の対応表で hex にする
  (`赤` → `#e60012`)。これは「赤」という事実の描画方法を決めているだけで、クラブ固有の色を
  推測してはいない。`source` を `wikipedia-hex` / `wikipedia-colorname` で区別する

### 3. baseball の team は「球団の変遷」なので、先頭の所属から色を引く

baseball の `team` は `巨人-日本ハム`(移籍)や `大洋・横浜`(改称)、
`西鉄・太平洋・クラウン-阪神-大洋-日本ハム` のように球団の変遷を連ねた文字列で、要素は
短縮名(`巨人`)である。

- 色は**先頭の `-` 区切り要素**から引く。その中の改称名を古い順に見て、最初に色が分かった
  ものを使う(`ダイエー・ソフトバンク` はソフトバンクの色になる)
- 短縮名 → 記事名の対応は手動表(`BASEBALL_TEAM_ARTICLES`)。**現存12球団と、独立した記事が
  ある大阪近鉄バファローズ、および同じ球団の旧称である「横浜」だけ**を載せる
- **消滅球団(阪急・南海・大洋・西鉄・東映・国鉄・ダイエー・大阪 など)は載せない**。
  記事名を引くと現行球団へのリダイレクトになり、当時とは違う色が付いてしまうため
  (南海ホークスは緑だが、リダイレクト先の福岡ソフトバンクホークスは黄)。
  推測色を入れるくらいならフォールバック配色にする
- football の `team` は単一のクラブ名で、`横浜F・マリノス` のように `・` を含むものがある。
  **`・` を区切り文字として扱ってはいけない**ので、リストごとに分解規則を切り替える

### 4. 主色・副色は出典に書かれた順のまま使う

youtuber のカードは「鮮やかな方を帯に回す」ようにしていたが、チームカラーではこれをしない。
Wikipedia のインフォボックスはチームカラーを公式の順で並べており、**鮮やかな方が主色とは
限らない**。FC東京(紺×赤)やヤクルト(紺×赤)で鮮やかな赤を主色にすると、別のチームに
見えてしまう。主色を帯に、副色を帯下のラインに置く。

帯の色は色相・彩度をほぼそのまま残し、淡いチームカラー(阪神・柏レイソルの黄)のときは
帯を暗く沈める代わりに**帯の上の文字を濃色に切り替える**(youtuber と同じ `light` 判定)。

### 5. カードに描くもの・描かないもの

- 中央左に名前の頭文字のディスク、下部にフルネーム、上部に区分
  (`プロ野球選手` / `サッカー選手` / `サッカー監督` / `クラブマスコット`)と所属チーム名
- **チーム名を必ず入れる**。動画やサムネイルで「誰の何」が分かるようにするため。baseball は
  先頭の球団名 + 移籍があれば `ほか`(`巨人ほか`)。長い名前は `…` で切り詰める。
  team が空の行はチーム行を出さず、区分だけにする
- 実写と誤認されないよう、右上に「イメージ」の札を必ず入れる(sekitsui/plant の概念イメージ、
  youtuber の象徴カードと同じ扱い)。SVGの `<desc>` にも写真・ロゴを使っていない旨を書く
- 図版は**自作の図形だけ**。帯の右側に薄く敷く抽象的な人型(円 + 自分で書いたパス1本)と、
  右下の競技のボール(野球=円と縫い目の曲線2本、サッカー=円と正五角形とそこから伸びる線)。
  **球団・クラブのロゴ・エンブレム・マスコット、リーグの公式ピクトグラム、競技団体の
  シンボルは参照していない**。人型は一般的な「頭と肩」の抽象表現に留める
- **ユニフォームの意匠は模倣しない**。阪神の縦縞のような特徴的な意匠は再現せず、単純な帯と
  ラインに留める

### 6. 生成カードはリポジトリ内に置き、raw URL で参照する

youtuber(ADR 00018)と同じく `images/baseball/` `images/football/` に置き、`image` は
raw URL、`image_page` は同じファイルの blob ページを指す。`tools/validate_csvs.py` の
画像URL許可リストは既に本リポジトリの raw / blob を通すので変更は要らない。

ただし youtuber(996枚・1.5MB)と違って**12,587枚・約19MB**になる。1枚1.5KB前後に収める
ため、youtuber のカードから次を削っている。

- 帯のグラデーションをやめてベタ塗りにする(1枚あたり約200バイト、全体で2.5MB)
- 角丸のクリップパスをやめ、帯を「上2角だけ角丸のパス」で描く
- `<desc>` を短くする、`aria-label`(`<title>` と重複)を落とす

GitHub Release のアセットにする案もあるが、CSVと画像が同じコミットに入って対応がPRの差分の
中で検証できる利点を優先した。将来さらに増えて重くなったら Release へ移すことになる。

## Consequences

- 両CSVの画像充足率が **baseball 37% → 100%**、**football 9% → 100%** になる。
  実写のある行(baseball 10,632行 / football 1,860行)は一切変わっていない
- チームカラーが付くのは baseball 6,082人中3,894人(64%)、football 6,505人中4,541人(70%)。
  残りはチーム名のハッシュ由来の配色になる
  - baseball のフォールバックは主に**消滅球団**(南海・阪急・大洋・ダイエー・西鉄・東映・
    国鉄 など)。同じ球団は同じ色になるので識別はできるが、実際の球団色ではない
  - football のフォールバックは主に**海外クラブとJFL以下のクラブ**、および team が空の
    1,787人(歴代の代表選手など、所属クラブが引けなかった人)
- 画像の出所が3種類になる(Commons の実写 / 本リポジトリの youtuber カード / 本リポジトリの
  選手カード)。実写だけが欲しい利用側は
  `https://raw.githubusercontent.com/soramimic/soramimic-wordlists/` で始まるURLを除外する
- リポジトリのファイル数が12,587増える。1ファイルが小さくファイルシステムのブロック
  (4KB)を1つ占めるので、作業ツリー上の見かけの容量(`du`)は約50MBになる。実データは
  約19MBで、テキストなのでgitのパックはよく効く
- Wikipedia のインフォボックスの書式に依存する。書式が変われば色が取れなくなるが、
  そのときは静かに消えるのではなくフォールバック配色に落ちる。baseball は対応表の14球団
  すべてで色が引けなければエラーで止める
- 月次バッチには入れない。新規行はカードが無い状態で追加されるので、手動で
  `python3 tools/gen_player_cards.py` を実行して埋める運用にする
- 選手が移籍するとカードのチーム名が古くなる。football の `team` は
  `tools/enrich_football_team.py --refresh` で引き直せるが、その後カードの再生成が要る
  (ファイル名は名前由来なので、再生成してもURLは変わらない)

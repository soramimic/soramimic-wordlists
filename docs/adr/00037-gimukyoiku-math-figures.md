# ADR 00037: 数学の語はプログラムで作図したSVGを割り当てる

- Status: accepted
- Date: 2026-08-02
- Supersedes: none
- Superseded by: none
- Related: 00027(実写・図版の引き方) / 00028(生成イメージ) / 00026(stationsの駅名標SVG)

## Context

gimukyoiku.csv に高校の語を足した結果、数学だけで95語が画像なしになった。
数学の用語は ja.wikipedia に語と完全一致する記事が無いか、あっても図が無い
ことが多い(`二倍角の公式` `内分点` `階差数列` など)。

一方でこれらは**図そのものが定義**である。判別式なら二次関数のグラフと x 軸の
交わり方、内分点なら線分上の点、無限等比級数なら正方形の分割。生成イラスト
(ADR 00028)に描かせると、座標も比も式も正確でないものが出てくる。

## Decision

**数学の語には `tools/gen_gimukyoiku_math_figs.py` でプログラム描画したSVGを
割り当てる。** stations の駅名標(ADR 00026)や sekitsui/plant の分類イメージと
同じ「作図して Release で配布する」流儀に乗せる。

- viewBox は 320x200 固定、自己完結SVG(外部フォント・画像を参照しない)
- ファイル名は生成イラストと同じ `gk_<sha1(語)先頭10桁>` で、拡張子だけ `.svg`。
  バケット振り分け(v1/v1b)も既存と同じ規則
- **座標は計算して決める。** 三角形の五心は外心・内心・重心の定義から算出し、
  メネラウスは比の積が1になることを、準線は焦点までの距離と準線までの距離が
  等しいことを数値で検証してから描く。目分量で点を置くと嘘の図になる
- **式が主題の語は無理に図にしない。** `二倍角の公式` `部分積分法` `底の変換公式`
  などは式を大きく組んだカードにする(既存のタイポカード173語と同じ扱い)

### 「AIイメージ」の札は入れない

ADR 00028 は生成イラストに「AIイメージ」の札を焼き込むと決めた。これは**実写と
誤認されるのを防ぐため**の措置である。プログラムで描いた線画の作図はそもそも
実写に見えないうえ、生成AIを使っていないので「AIイメージ」は事実として誤りに
なる。よってこの札は入れない。manifest には `method: "svg"` と記録して、生成
イラスト(`sd` / `gpt-image`)と区別できるようにする。

## Consequences

- 数学95語が正確な図版を持つ。SVGなので拡大しても劣化せず、95枚で448KBと軽い
- 図の正しさはコードで担保されるが、**コードが間違っていれば静かに嘘の図になる**。
  追加・修正時はレンダリングして目視確認する手順を省かない
- 他教科にも同じ手が使える(理科の実験装置、技術の製図など)。実際 imggen 側には
  製図の投影法を描く `gen_projection_figs.py` の前例がある
- 拡張子が `.svg` になるので、既存の `gk_*.jpg` を前提にした処理があれば追随が要る
  (`postprocess_upload.py` は生成イラスト専用なので影響しない)

# ADR 00033: pokemon のカードを図鑑端末風にし、モチーフの汎用シルエット(PhyloPic のPD素材 + 架空モチーフは自作のCC0素材)を敷く

## Context

ADR 00002 で決めた「型色カード」は、上部にタイプ2色の対角グラデーション帯、その右下に
全国図鑑No、下部に名前とタイプチップ、という構成だった。**キャラクター造形を使わないという
方針は正しいが、絵として情報が薄い。** 1203枚のカードは「色が違うだけの同じ形」で並び、
タイプが同じポケモンは見分けが付かない。

ADR 00032 で `genus`(分類名)・`height_m`・`weight_kg`・`rarity`・`evolves_from` が入り、
**カードに載せられる事実が増えた**。事実を並べるならレイアウトは表を持つ形が自然で、
「図鑑の端末」という見立てがそのまま使える。

さらに、絵の側にも1つ材料がある。**「そのポケモンのモチーフになった生物」は、キャラクター
造形とは別の情報である。** ピカチュウの分類名は「ねずみポケモン」で、これは PokéAPI にある
一次情報の事実である。ネズミの汎用シルエットはピカチュウの絵柄を1画素も含まないが、
「ネズミ系のポケモンだ」ということは伝わる。ADR 00024 で「実在のロゴ・エンブレム・肖像・
キャラクターデザインは借りないが、汎用のオープンライセンス素材は帰属を付けて使ってよい」と
方針を緩めてあるので、生物のシルエット素材を借りる余地もある。

なお ADR 00024 の表現は「実在のロゴ・エンブレム・マスコット・肖像・キャラクターデザインは
借りない」であって、生物の汎用シルエットはそのどれにも当たらない。

## Decision

### 1. 意匠を「図鑑端末風」に変える(ADR 00002 の意匠の記述を更新する)

寸法は 320×200 のSVGのまま、内側の構成を3段に組み替える(`tools/gen_pokemon_typecards.py`)。

- **上部**: 黒いベゼル帯(高さ30)。左に赤・黄・緑のLEDランプ(赤だけ大きくハイライト付き)、
  右端に monospace の `No.0025`。機械の筐体であることをこの帯だけで示す
- **左**: 「画面」パネル(x=12,y=38,126×94、角丸8)。タイプ2色の**縦**グラデーションで塗る
  (単タイプは同色2点なので単色べた塗り)。この中に**モチーフのシルエット**を白の透かし
  (`fill-opacity=0.42`)として敷く
- **右**: ぶんるい / たかさ / おもさ の3行のデータ表(ラベルは小さい灰色、値はその下、区切り線付き)。
  「りんごあめポケモン」のような長い値は表の幅に収まるまで font-size を落とす
- **最下部**: 名前(1行で入らなければ2行)とタイプチップ、`rarity` があれば名前の右にバッジ、
  チップ右の余白に小さく右揃えで「初登場 <版名>」「<進化前>から進化」(ADR 00032 の取り決めどおり)
- 配色はタイプ色がコミュニティ慣習の色である点も含めて ADR 00002 のまま。本体は生成り色、
  文字は墨色で、端末の外装であることを色でも示す
- **SVGが自己完結であること(外部フォント・外部画像を参照しない)、文字をテキスト要素のまま
  保持すること、1 id につき1枚で表記ゆれ3行が同じカードを共有すること、ファイル名と
  リリース振り分けの規則は変えていない**。差分はカードの中身だけなので、既に配布済みの
  URLはそのまま同じポケモンを指す(中身を上書きアップロードする運用は ADR 00032 のとおり)
- グラデーションとクリップパスの要素idには名前由来のキーを入れる。複数枚をHTMLへ
  インライン展開したときに定義が衝突しないようにするため

### 2. モチーフのラベルは `tools/pokemon_motifs.json` に持つ

全国図鑑Noをキーに `{name, motif, confidence}` の対応表を置く。**1025種**ぶんあり、
モチーフラベルは**225種類**。シルエットはラベル単位で用意するので、1025種を225枚で賄える。

- ラベルは種単位で振る。フォーム(アローラライチュウ、メガリザードンX)は
  **種の図鑑Noで引く**ので、本体と同じシルエットになる
- 判定は次の2段で行った
  1. **分類名(`genus`)とポケモンの一般知識**からLLMで判定する。「ねずみポケモン」のように
     分類名がモチーフを言い当てている種は、これで一次情報から決まる
  2. `confidence` が `low` になったものだけ、**PokéAPI の日本語フレーバーテキストと
     Web上の解説を判定の入力に足して再判定**する
- 最終的な `confidence` の分布は **high 707 / medium 296 / low 22**

### 3. フレーバーテキストは情報解析の入力に使うが、リポジトリには保存しない

ADR 00032 で「公式のフレーバーテキストは収録しない」と決めた。**この決定は変えない。**
今回はそれを収録せずに**判定の入力としてだけ使う**。

- フレーバーテキストは著作物である。しかしそこから「モチーフはネズミ」という**事実・
  アイデアを抽出する**のは、著作権法30条の4がいう**情報解析**であり、享受を目的としない限り
  認められる(ADR 00019 でポートレートの代表色を求めたのと同じ考え方)
- **出力はラベル1語**で、元の文章との実質的類似性を持たない。複製にも翻案にも当たらない
- **フレーバーテキスト自体はリポジトリに置かない。** 中間処理はローカルで完結させ、
  コミットするのはモチーフのラベルだけにする(ADR 00019 で取得画像を `tools/.cache/` 止まりに
  したのと同じ扱い)

### 4. モチーフの判定は**このリポジトリの解釈**であり、公式の設定ではない

分類名のような一次情報がある種を除き、「何がモチーフか」は公式が明言していない。ここで
付けたラベルは、**シルエットを選ぶための手がかりとしてこのリポジトリが決めたもの**である。

- ADR 00025 で分野の色を「このリポジトリが見分けやすさのために決めたもの」と明記したのと
  同じ扱いにする。外部から「ピカチュウの公式モチーフはネズミ」と参照されると誤解になるので、
  本ADRと README に明記する
- 迷ったときは**具体的なラベルを当てるより粗いラベルに寄せる**。嘘の生物を描くより、
  抽象的なラベル(`その他` 等)でシルエット無しに落ちる方を選ぶ

### 5. **外部から借りる**シルエット素材は PhyloPic の**パブリックドメインのものだけ**を使う

出典は [PhyloPic](https://www.phylopic.org/)(生物のシルエット集)。取得は
`tools/fetch_motif_silhouettes.py`。

- **CC0 / Public Domain Mark の素材のみ採用する。** PhyloPic には CC BY / CC BY-SA の素材も
  多いが、**帰属表示と継承の義務がカード(=このリポジトリの配布物)側に及ぶ**。カードは
  raw URL / Release アセットとして1枚ずつ直リンクされる使われ方をするので、下流に義務を
  背負わせたくない。PD素材が見つからないラベルは**シルエット無しで済ませる**
  (ADR 00024 で Material Symbols の Apache 2.0 を受け入れたのとは判断が分かれるが、
  あちらは1セットの帰属を README とSVGの `<desc>` で一括して書けるのに対し、PhyloPic は
  素材ごとに作者が違い、146枚ぶんの個別帰属をカードごとに背負うことになる)
- **ラベル→学名**は `tools/motif_taxa.json`(225ラベル。うち学名が引けるのは149、
  架空・非生物のラベル76は `null`)。学名で PhyloPic のノードを引き、そのクレードの画像から
  PD のものを選ぶ。**学名 `null` のラベルは PhyloPic の対象外**で、そのうち16ラベルは
  決定9の自作素材で埋めてある
- **成果物の台帳**は `tools/motif_silhouettes.json`(ラベル→ファイル名・素材の出所
  (`source`)・学名・ノード名・PhyloPicのUUID・ライセンスURL・作者・ラスタライズ検査値)。
  PhyloPic 由来は **146ラベル**で、ライセンス内訳は **CC0 122 / PD Mark 24**。
  これに決定9の自作素材16ラベルが加わって台帳は**162ラベル**。素材の出所を後から必ず
  辿れるようにする
- 画像は `images/pokemon_motifs/<sha1(ラベル)先頭10桁>.svg`。日本語のファイル名を避けつつ
  ラベルと1対1に保つため。取得したSVGは図形要素だけを抜いて座標を丸め、最小限のSVGに
  作り直す(色は持たせない。塗りはカード側で指定する)。**祖先の `<g transform>` は行列に
  畳んで保持する**(無視すると描画が枠外へ飛んで真っ白になる)
- **1枚 24KiB 上限**。1203枚のカードにインライン展開するので、細密すぎる素材は使わない
  (PhyloPic 由来の実測は最大24,548バイト・平均7.3KB。決定9の自作素材はこれより
  はるかに軽く、上限を4KiBに絞ってある)

### 6. シルエットは**モチーフ生物の汎用的な形**であって、ポケモンの造形ではない

ピカチュウのカードに敷くのは「ネズミ(`Mus`)の一般的なシルエット」で、
**ピカチュウの姿・イラスト・ドット絵は一切使わない。** ADR 00002 の「キャラクター造形を
使わない」方針と整合する。シルエットは種ごとに1枚ではなくラベルごとに1枚なので、
同じモチーフのポケモンには同じ形が敷かれる(ピカチュウとライチュウは同じネズミ)。

### 7. 素材の品質はラスタライズして機械的に検査する

PhyloPic の素材は投稿物なので書き方が揃っていない。そのまま使うと「黒い矩形」や
「真っ白」になるものが混ざる。chrome でラスタライズして塗り面積の比を測り、次の3つを弾いて
**次の候補画像を試す**(1ラベルにつき先頭8件まで)。

- **白黒反転素材**(背景を塗って生物の形を抜いてある): 外部と繋がった背景の比が 0.04 未満
- **ほぼ空**: 塗りの比が 0.055 未満
- **輪郭線だけの線画**: 塗り / (塗り + 囲まれた背景) が 0.45 未満

chrome が無い環境では検査を飛ばして警告するだけにする(検査は品質向上のためで、必須依存に
しない)。検査値は台帳に記録して、後から基準を変えたときに影響範囲が分かるようにする。

### 8. シルエットが無いカードは画面に白い `?` を出す

素材が無いことを空白にせず、「データ未取得」の意で `?` を出す。図鑑端末という見立てに
合うし、シルエットの取得漏れが目視で分かる。

### 9. 架空・非生物のモチーフは**このリポジトリで描いた自作シルエット(CC0)**で埋める

**PhyloPic は生物のシルエット集なので、ドラゴン・妖精・ゴースト・岩・果実のような
架空/非生物のモチーフは原理的に存在しない。** これらは `tools/motif_taxa.json` で学名が
`null` になり、決定8のとおりカードに `?` が出る。ところが `?` になる種は**種数の多い
ラベルに集中している**(ドラゴン43種・妖精22種・ゴースト21種)ので、ここが埋まらない限り
「タイプが同じポケモンが同じ絵に見える」問題が主要な進化系統で残る。

そこで、**種数の多い16ラベルのシルエットをこのリポジトリで描き起こした。**

- **対象と効く種数**: ドラゴン43 / 妖精22 / ゴースト21 / 岩16 / 果実13 / タネ8 /
  ロボット8 / 天体7 / 木7 / 氷5 / タマゴ5 / 剣3 / 歯車3 / 磁石3 / 野菜3 / 雲1 = **168種**
- **ライセンスは CC0、作者はこのリポジトリ**(台帳の `"source": "self"` /
  `"contributor": "soramimic/wordlists"` / `"license"` は CC0 のURL)。**外部から素材を
  持ち込まない**(フォントの字形・絵文字・既存アイコンセットの流用もしない)ので、
  PhyloPic の素材と同じく下流に帰属義務を負わせない
- **台帳で出所を区別する。** 既存の PhyloPic 由来エントリにも `"source": "phylopic"` を
  明示した。自作エントリは学名を持たない(`taxon` キー無し)ので、台帳を見れば
  「学名 `null` だが素材はある」状態が判別できる。`tools/motif_taxa.json` は
  **学名の対応表**なので自作ラベルも `null` のままにする(嘘の学名は入れない)
- **`tools/fetch_motif_silhouettes.py` は自作素材を触らない。** `--refresh` でも
  `source: "self"` のエントリとファイルは取得対象・掃除対象の両方から除外する
  (学名が `null` のラベルの残骸を消す処理に巻き込まれると自作素材が消えるため)。
  未取得の警告にも出さず、代わりに自作素材のファイルが失われていたら警告する
- **描き方の制約**(素材の性質をPhyloPic由来と揃えるため):
  単色の塗りだけ(`stroke` を使わない。`fill` はカード側が与える) / `viewBox` は輪郭に
  ほぼ外接させる(カード側が枠に合わせて拡大縮小するので余白は損になる) /
  **100px程度に縮めても何か分かる**こと(細い線・小さな穴・細かい装飾は使わない) /
  1ファイル4KiB以内(実測は最大3,969バイト・平均1.1KB) / 出力形は PhyloPic 由来と同じ
  `<svg xmlns viewBox><path d="…"/></svg>` の1行
- 塗りは1つの `<path>` に閉じたサブパスを重ねて表現する(nonzero)。目や中心穴は
  **逆巻きのサブパス**で抜く。`fill-rule="evenodd"` にすると図形の重ね合わせが
  打ち消し合って穴だらけになるので使わない
- **形が「何に見えるか」は目視で確認して描き直した。** 一覧をPNGにレンダリングして
  100px相当・56px相当でも判別できるかを見る、という手順を繰り返している。ゴースト・果実・
  ロボット・天体・歯車・雲は一度で通ったが、ドラゴン・タネ・木・野菜は3〜4回描き直した
  (ドラゴンは翼が小さいと首の長い恐竜に見え、タネは水滴形+芽だと洋ナシに見えたので
  どんぐり型にした。磁石は真上を向いた U 字が文字の「U」に見えたので傾けた)
- **自作素材の対象を増やすときは同じ手順を踏むこと。** 残る60ラベルは1〜3種のものが多く、
  「効く種数 ÷ 描く手間」が急に悪くなるので、いまは16ラベルで止める

## Consequences

- **1203枚のうち 1078枚(90%)にシルエットが入る。** 種で数えると 1025種のうち 917種。
  内訳は PhyloPic の146ラベルで 876枚(73%)、決定9の自作16ラベルで **+202枚(+17ポイント)**。
  カードとして見分けが付くようになり、タイプが同じポケモンが同じ絵に見える問題は解消する
- **入らない63ラベルの内訳**は、学名が引けず自作もしていない架空・非生物のモチーフ60ラベルと、
  PhyloPic に PD 素材が無い3ラベル(アメンボ・マンボウ・ミーアキャット)。**「生物のシルエット
  集から引けないもの」に素直に対応している**。残る60ラベルは1ラベル1〜3種のものが多いので、
  カードでは125枚(10%)が `?` のまま残る
- **カードSVGは全枚数が作り直しになる。** 意匠が変わるうえシルエットが埋め込まれるため。
  ファイル名は名前由来で変わらないので、Release へは `--upload`(`--only-missing` なし)で
  全枚数を上書きすること(ADR 00032 と同じ)
- **1枚あたりのバイト数が増える。** シルエットのパスがカードごとに埋め込まれる
  (PhyloPic 由来が平均7.3KB、自作が平均1.1KB)。共有の `<defs>` に逃がす手もあるが、カードは1枚ずつ直リンクされるので
  **自己完結SVGであることを優先する**(ADR 00024 と同じ判断)
- **カード画像に PhyloPic の PD 素材と、このリポジトリ自作の CC0 素材が含まれる。**
  どちらも帰属義務は生じないが、出所は台帳(`tools/motif_silhouettes.json`)の `source` で
  辿れるようにし、README の出典欄にも両方を書く。**Material Symbols の Apache 2.0 のような
  帰属義務は pokemon のカードには及ばない**(pokemon のカードは Material Symbols を含まない)
- **自作シルエットは手で描いたデータなので生成スクリプトが無い。** 直すときは
  `images/pokemon_motifs/<sha1(ラベル)先頭10桁>.svg` を直接編集し、決定9の制約
  (単色1パス・外接 viewBox・100pxで判別可能・4KiB以内)を守って目視で確認すること。
  台帳の `source` を `self` のままにしておけば取得スクリプトは上書きしてこない
- **モチーフのラベルには生成スクリプトが無い。** LLM判定の結果を人が確認して確定させた
  対応表なので、`tools/pokemon_motifs.json` は手で保守するデータである。
  **新世代が追加された回は新種のラベルを足すこと。** 足さなくてもカードは生成でき、
  シルエットが `?` になるだけなので壊れはしない(静かに劣化するので、`?` の枚数が
  増えていたら未ラベルを疑う)
- シルエットの取得は月次バッチに入れない。PhyloPic API への問い合わせと chrome での検査に
  時間がかかるので手動実行の運用にする(ADR 00019 の色の解析と同じ扱い)
- ラベルは種単位なので、**フォームは本体と同じシルエットになる**。メガフシギバナも
  フシギバナと同じカエルの形で、フォームごとの造形差はカードに出ない。これは受け入れる
  (フォームの造形差はキャラクター造形そのものなので、そもそも描けない)

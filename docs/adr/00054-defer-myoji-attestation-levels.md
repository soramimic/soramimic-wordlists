# ADR 00054: 名字の確認段階と人口順位の再設計を保留する

- Status: accepted
- Date: 2026-08-15
- Supersedes: none
- Superseded by: none
- Related: 00038 / 00050 / 00051 / 00052 / 00053

## Context

`myoji.csv` は空耳動画での利用に加えて、表記、読み、順位、実在性を持つ公開辞書としても
利用される。一般Web再調査後、読みの信頼性と網羅性を一つの `verified` だけで表す代わりに、
次のような確認段階を追加する案を検討した。

- 根拠のない候補
- 地名や創作人物で表記と読みだけを確認した用例
- JMnedictで `surname` として収録された辞書上の姓
- 専門組織が運営する名字データベースや、手順の明らかな研究資料で確認した姓
- 現代または歴史上の具体的な人物で表記と読みを確認した姓

この案では、地名は漢字列の読みを、創作人物は姓としての創作上の使用を示すが、現実の姓の
実在までは示さない。具体的人物は存命者に限らず、歴史資料中の人物も対象にできる。人物を
示す一次資料と信頼できる二次資料は、実在性の段階を分けず、必要なら証拠品質を別に記録する。

情報源ごとの性質も異なる。JMnedictは編集・分類された固有名詞辞書であり、CC BY-SA 4.0の
条件で再配布できるが、具体的人物の存在を全エントリについて保証するものではない。
名字由来netは企業と専門家が責任を持って調査・運営する名字データベースで、姓としての
信頼性は単なる投稿サイトより高い。一方、個々の読みから原資料まで常に追跡できるとは限らず、
大量取得・再配布には通常のWeb閲覧とは別の利用条件や公式データ提供の確認が必要になる。

静岡大学城岡研究室の旧「日本の姓の全国順位データベース」に基づいて順位や世帯数を付ける
案も検討した。しかし同データの基礎は当時の市販電話帳データで、公開辞書へ一括再配布できる
明確なオープンライセンスを確認できない。電話帳掲載件数は戸籍上の世帯数ではなく、時点、
固定電話の掲載有無、地域等の偏りもある。また頻度は姓の表記に対する値であり、同じ表記の
複数の読みに割り当てられる頻度ではない。

### 並行して検討した順位・件数の取得方法

並行検討では、名字由来netと同等の推計を再現する方法から検討を始めた。国勢調査等は
姓別人口を公表していないため、「政府発表統計と全国電話帳データ」は、電話帳内の地域別の
姓構成比を公表人口・世帯数へ拡大する推計と考えられる。しかし利用した電話帳の版、掲載率の
補正、異体字の統合、少数値の丸め等が公開されていないため、名字由来netの値を完全再現する
ことはできない。独自に再現するなら、電話帳の個人名を整理し、市区町村別の姓比率を求め、
公表人口で拡大し、推計時点・標本数・誤差を付ける必要がある。

候補となる既存資料も比較した。

- 立命館大学の公開Excelは、研究で使った全件データではなく、都道府県ごとの代表的な
  上位10姓の集計であり、全国辞書の順位表には使えない
- 静岡大学のCSVは1997年版電話帳に基づく25,078表記で、`sei`、`rank`、`number`の3列を持ち、
  読みは持たない。`number`は電話帳登録件数であり、人口や戸籍上の世帯数ではない
- 静岡大学CSVと現行 `myoji.csv` の表記一致は22,533件、89.9%で、上位1,000件は100%、
  上位5,000件は98.7%だった。動画で頻出姓を優先する指標としては実用的だが、希少姓、
  固定電話非掲載世帯、1997年以降の変化を十分に表さない
- Wikidataから世帯数・人口は得られない。現行 `rank` は姓を持つ著名人物項目の件数なので、
  人口順位とは上位の並びも異なり、著名人の分野と整備状況に偏る
- 商用名字CSV・APIは網羅性と更新性を得やすいが、閲覧・内部利用だけでなく、GitHub上の
  派生CSV、加工、商用・非商用の再利用、契約終了後の公開を許す二次配布権が必要になる

静岡大学CSVを採る場合は、順位と件数を読みの各行へ重複させず、表記単位の頻度表と
表記・読み表を分離する案が最も整合的だった。`number`も `household_count` ではなく
`phonebook_listing_count`、順位も `directory_rank` とし、1997年という基準年を保持する。
現在のWikidata順位を残すなら `notability_rank` と改称し、人口順位と併存させる必要がある。

全国電話帳を自前集計する計算自体は難しくないが、実際の費用と作業は元データの取得、
個人と屋号の分離、姓と名の分割、重複・連名・転居の処理、旧字体・異体字の正規化に集中する。
個人名簿を再配布せず名字別の集計値だけを公開するなら、個人情報や個々の記載を公開する場合
よりリスクは大きく下がる。個人との対応を排除した統計情報は一般に個人情報ではなく、名字、
独自集計した件数、順位という事実そのものと、元電話帳の創作的な選択・体系的構成も区別できる。
内部複製も非享受目的の情報解析として許容される余地がある。このため、適法に入手した古い
電話帳から既成ランキングを転載せず独立集計する案は、当初の想定より現実的である。

実施するなら、生の氏名・住所・電話番号をGit管理外に限定し、コピー防止を回避せず、元製品の
EULAで抽出・自動処理・派生統計の公開が禁じられていないことを確認する。公開物は表記、独自
集計件数、順位、基準年だけとし、例えば40件未満を非公開にすれば、統計の不安定さ、個人推測、
誤抽出も抑えられる。それでもデータ入手、規約確認、正規化規則、再現可能な集計器、生データの
安全な管理が新たに必要になるため、今回の辞書整備を継続する理由にはせず、実装を保留する。

また本リポジトリには全体をApache-2.0とするルートライセンスがなく、CSVにはSudachiDict、
JMnedict、Wikidata、Wikipedia等の条件が列・出典ごとに混在している。したがって静岡大学
データの問題は「Apache-2.0へ統一できない」ことではなく、再配布範囲が標準ライセンスほど
明確でないことである。将来導入する場合は、データまたは列ごとのライセンス表示と
第三者資料のnoticeを先に整理する必要がある。

2026-08-15時点の `myoji.csv` は91,836表記、107,063表記・読みを収録し、そのうち
71,727表記、79,175表記・読みがJMnedictと一致する。`verified=yes` は40,274組である。
一般Web調査はADR 00053の基準で完了し、4,509組の `web_person` 根拠について原URL本文の
表記と読みを監査済みである。現在の成果は、候補の網羅性と人物による確認を混同せず利用できる
区切りに達している。

## Decision

確認段階、証拠種別、表記単位の頻度を分離する設計は妥当だが、現時点では導入を保留する。
既存成果を巻き戻さず、次の現行仕様を維持する。

- `verified=yes` は、現代または歴史上の具体的人物について同じ表記と読みを確認したことを示す
- `verified=no` は誤りや非実在を意味せず、具体的人物で未確認であることだけを示す
- `evidence_sources=jmnedict` は辞書上の姓収録を示すが、単独では `verified=yes` にしない
- `official_web` と `web_person` は、原ページで同一人物の表記と読みを確認できた場合だけ採用する
- 現在の `rank` はWikidata上の著名人数による参考順位とし、人口順位や世帯順位とは呼ばない
- 地名、創作人物、名字サイトの掲載だけを理由に既存行を `verified=yes` へ変更しない

この判断に伴い、次の変更は行わない。

- L0からL4までの確認段階や `attestation_kind` 列の追加
- JMnedictの全 `surname` エントリを母集合とする辞書の再構築
- 名字由来net等からの大量取得、順位・人数・解説の再配布
- 静岡大学の旧順位データに基づく `rank` や `household_count` の付与
- 立命館大学の上位姓集計や、権利未確認の電話帳データによる順位の補完
- 現在のWikidata著名人順位を、人口順位または世帯順位として扱うこと
- 地名や創作物を根拠とする表記・読み候補の追加調査

将来、再配布可能な人口・世帯データのライセンス、更新手順、表記単位と読み単位を分離した
スキーマ、または適法入手した電話帳を安全に独自集計できる手順、利用側の明確な要求が揃った
場合は、新しいADRで再検討する。その場合も、人口頻度と人物実証、辞書収録、非人物用例を
一つの序列へ押し込まず、独立した属性として設計する。

## Consequences

- 既に完了した一般Web調査と人物証拠台帳をそのまま利用でき、追加の大規模調査や巻き戻しは不要
- 権利や時点が不明確な電話帳由来の順位・件数を、人口・世帯の精密な値として公開せずに済む
- 動画側は従来どおり `rank`、`verified`、`evidence_sources`を目的に応じて組み合わせられる
- 辞書収録、専門名字データベース、研究資料、地名、創作物の違いを細かく検索する機能は増えない
- JMnedictにない希少姓や、具体的人物を発見できない実在姓は引き続き `verified=no`になりうる
- 読みの網羅性と人口頻度を保証する辞書ではないことを、利用側が列の定義から理解する必要がある

# ADR 00017: plant.csv の科・属(family/genus)列

- Status: accepted
- Date: 2026-07-28
- Supersedes: none
- Superseded by: 00059-plant-family-generated-fallback.md (QID取得をP18から分離する判断)

## Context

plant.csv の分類情報は `class` 列の大分類(双子葉/単子葉/裸子植物/シダ植物/コケ植物/藻類)だけで粒度が粗い。動画レイアウトで「写真 + 和名 + ヒルガオ科サツマイモ属」のように出したい(依頼元 soramimic-video の `plant_card`)。

sekitsui.csv では ADR 00015 で目(order)・科(family)を付けた。植物は目より **科・属** が一般的な言及単位なので、同じ仕組みで階級だけ変えたい。

PR #54 / #57 で `wikidata` 列(画像の取得元 taxon の QID)が 5,799/6,542 行(88.6%)に入っており、**同定という一番難しい工程は済んでいる**。残るのは QID から親タクソン(P171)を辿って科・属を取る処理だけで、これは `tools/enrich_sekitsui_taxonomy.py` とまったく同じ形をしている。

一方、植物には動物と同じ和名を持つものが多い(スギ・ハス・ホトトギス・カマツカ等)。sekitsui では `wikidata` が空の行を和名から逆引きして補っているが、植物で同じことをすると動物側のタクソンを引いて「スギ = ○○科」が魚の科になりかねない。

## Decision

- `plant.csv` に `family`(科)・`genus`(属)列を `extinct` の後ろに追加する。値は日本語の階級名(例 `バラ科` / `サクラ属`)。sekitsui の `order`/`family` と同じく言語サフィックスは付けない(学名にフォールバックすることがあるため `_ja` はむしろ不正確になる)
- 木を辿る処理は `tools/taxonomy.py` に切り出し、動物(目・科)と植物(科・属)で共有する。呼び出し側は「上位から順に並べた階級のリスト」だけを渡す。先頭の階級が幅優先探索の打ち切り点になる(下位の階級はそれより下にあるので取り逃さない)
- 植物用の入口は `tools/enrich_plant_taxonomy.py`。キャッシュは `tools/.cache/plant_taxonomy.json` と別建てにする
- 表示名の優先順は動物と同じ「階級付きの日本語別名(skos:altLabel、語尾が科/属のもの) > 日本語ラベル > 学名(P225)」
- **無制限な和名逆引きはしない**。後続の ADR 00059 により、種ランクの日本語ラベル完全一致候補を既存 `class` の植物クレード内に制限し、一意な場合だけQIDを補う。複数候補や候補なしは空のままにする
- WDQS へのクエリは POST(`wpnames.sparql_post`)で投げる。VALUES に数百件を並べると GET では URI が長すぎて HTTP 414 になるため。共通化にあたって動物側も POST に揃えた(結果は同じ)
- 既定では family/genus が空の行だけ埋める(冪等)。`--refresh` で全行引き直し
- 月次バッチではQID補完→分類補完→P18取得の順で実行し、新規行も同じ安全条件で補完する

## Consequences

- 科・属での絞り込み・表示ができるようになる。QID を持つ 5,799 行のほぼ全件に科が入り、CSV 全体では約 88% が埋まる
- P18がない行でも安全に一意同定できた場合はQID・科・属を保持する。曖昧・未発見の行は空のままとし、利用側は空でも動くこと
- 値はスナップショットであり、分類体系の改訂には自動追従しない。気になったら `--refresh` を手動実行する
- 動物側は `tools/taxonomy.py` を使うリファクタが入る。挙動が変わらないことは、キャッシュを固定した状態で新旧の実装を通して sekitsui.csv を書き出し、バイト単位で一致することを確認して担保した
- 属は科より下位なので、種→属の P171 が張られていない行では属だけ空になることがある(科は取れる)

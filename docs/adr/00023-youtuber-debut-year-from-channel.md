# ADR 00023: youtuber.csv の debut_year をチャンネル開設年で補い、既存行の空欄を埋める

- Status: accepted
- Date: 2026-07-29
- Supersedes: none
- Superseded by: none
- Related: 00011(youtuber/vtuber リストの収録基準) / 00014(既存行を劣化させない・空欄補完のみ)

## Context

youtuber.csv の `org`(所属)・`debut_year`(活動開始年)の欠損が多い。実測(996人時点)
では debut_year が youtuber 744人中542人・vtuber 252人中48人で `NA`、org は同 603人・
112人が `NA` だった。絞り込み(`org~=ホロライブ`)や年代での並べ替えが効かない。

原因は情報源の薄さで、`debut_year` は Wikidata の P2031(活動開始)だけを見ている。
P2031 は人物項目に入っていないことが多い。org も P108(雇用主)/P463(所属組織)/
P1416(所属)だけを見ており、**現在 `NA` の693人は、これら3プロパティを引き直しても
1人も埋まらない**(Wikidata 側に値が無い)。

一方、YouTuber の項目には **P2397(YouTubeチャンネルID)に修飾子 P580(開始時点)**が
付いていることが多い。これはチャンネルの開設時点で、ja.wikipedia の
Infobox YouTube personality の `years_active` も「チャンネル作成から中止、終了までの年」と
定義されており、このリストの「活動開始年」として実質同じものを指している。

## Decision

1. **`debut_year` は P2031 を優先し、無ければ P2397 の P580(チャンネル開設年)を使う。**
   取得は既存の `fetch_attrs` の SPARQL に `OPTIONAL` を1本足すだけで、
   取り消し済み(DeprecatedRank)の文は除く。複数チャンネルがあるときは最も古い年を採る
2. **既存行の `org` / `debut_year` は空欄補完のみ行う**(ADR 00014 の scientist と同じ扱い)。
   セルが空か `NA` のときだけ書き込み、入っている値は取得結果が違っても書き換えない。
   補完した人数は実行ログに出す

### Wikipedia の infobox からの補完は見送る

`org` を埋めるにはWikipedia記事の infobox(`network` / `事務所` / `agency` 等)を
読むしかないが、全972人の記事wikitextで実測したところ **org欠損693人のうち候補が
取れるのは195人(28%)** にとどまり、しかも値の質に問題が残る。

- `network` は空欄やテンプレートのコメント(`<!-- 所属事務所 … -->`)のままの記事が多い
- 過去の所属が期間注記付きで併記される(「A（2016年 - 2018年）B（2020年 - ）」)ので、
  現在の所属だけを機械的に取り出せない
- `レーベル` / `label`(音楽レーベル)や `associated_acts`(関連人物)が混ざり、
  事務所ではないものを org に書きうる

`debut_year` も infobox の `years_active` を足せば補完率が 60% -> 83% に上がるが、
`[[2017年]][[5月1日]] -` / `{{Plainlist|…}}` / HTMLコメント入りなど表記が揺れる。
どちらも**毎回1000件近い記事wikitextの取得とパースを月次バッチに足す**ことになるため、
本ADRでは構造化データ(Wikidata)で取れる範囲に留め、infobox パースは別の判断とする。

## Consequences

- `debut_year` の欠損が 576人 -> 228人(欠損率 59% -> 23%)になる。補完した348人の年は
  すべて 2005年(YouTube開設)以降で、既存値の書き換えは0件
- **トレードオフ: 「活動開始年」の意味が2種類混ざる**。P2031 由来の行は本人の活動開始
  (芸能活動の開始年でありうる)、P580 由来の行はチャンネル開設年になる。列の用途が
  「だいたいいつからの人か」なので許容する。厳密な区別が要るなら列を分ける
- `org` の欠損(693人)は今回変わらない。Wikidata 側に値が増えれば次回以降の空欄補完で
  自動的に埋まる
- 空欄補完は既存行を触るので、月次PRの差分に「追記」以外が混ざる。ログに人数を出し、
  値の書き換え(劣化)は起こさない実装にしてある

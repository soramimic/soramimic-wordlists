# ADR 00027: gimukyoiku(義務教育)への画像付与

- Status: accepted
- Date: 2026-07-29
- Supersedes: none
- Superseded by: none
- Related: 00022(gimukyoiku 本体) / 00021(insect。EXCLUDED の流儀) / 00006, 00010(fictional。AI生成画像のRelease配布の前例)

## Context

gimukyoiku.csv(1867行)には画像列が無かった。語は学習用語(光合成・連立方程式)、人名・作品名(夏目漱石・枕草子)、器具(リコーダー・ガスバーナー)が混在し、既存リストと事情が違う点が2つある。

1. **taxon や人物のような機械的な引き当てキー(QID)を持たない**。sekitsui/plant/insect は取得時の taxon QID から P18 を引けたが、gimukyoiku は語の文字列しか無く、和名からの引き当てには同名異義の取り違えリスクがある(教科をまたぐ同音異義「分子」「パス」を敢えて収録している ADR 00022 の設計上、なおさら)
2. **画像がそもそも存在しない語が多い**。サンプル計測(108語)では ja.wikipedia に記事がある語 76%、リード画像まで取れる語 43%。特に英語の文法用語はほぼ 0%

## Decision

### 実写・図版は「完全一致記事のリード画像」だけを使う

`tools/enrich_gimukyoiku_images.py`(手動実行。自動更新バッチ対象外)で付与する。

- **語と完全一致する ja.wikipedia 記事**(リダイレクト追従あり)の**リード画像**(pageimages、`pilicense=free`)だけを採用する。検索・部分一致・曖昧さ回避ページの先頭候補などの「それらしい」引き当てはしない。取りこぼしより取り違えを嫌う設計(insect の同名異義ガードと同じ思想)
- 画像は **Wikimedia Commons に実在するファイルだけ**使う(jawiki ローカルの非自由ファイルを除外)。`image` は Special:FilePath、`image_page` は Commons の File: ページ(ライセンス確認先)。既存リストと同じ形式
- `wikidata` 列には画像の取得元になった記事の QID を入れる(画像とセットで埋まる。sekitsui/plant と同じ扱い)
- 完全一致でも語義が違う誤マッチ(教科の文脈と別の意味の記事が同名で存在するケース)は、付与結果の全件 AI レビューで洗い出し、スクリプト内の **EXCLUDED**(語→理由)に恒久除外として追記する。CSV から消すだけでは再実行で再付与されるため(insect の EXCLUDED と同じ流儀)
- 初回付与(2026-07-29)は **825/1867 行 = 44%**(理科 130・社会 126・美術 115 に対し英語 28。分野差はサンプル計測どおりで取得漏れではない)
- **リード画像が無い記事は Wikidata の P18(画像プロパティ)をフォールバック**で引く(2026-07-30 追加)。記事の代表画像が未設定でも P18 が付いていることが多い(火成岩・版画・金剛力士像など)。P18 は Wikidata 側で人手により選ばれた代表画像なので完全一致方式と同水準の精度だが、英語圏由来の誤結合(発音→pronunciamento 等)があるため、追加分も全件 AI レビューして EXCLUDED を増補した。P18 フォールバックで実写・図版は 948 行まで増えた
- **生成イメージ(ADR 00028)の行は、実写・図版が取れたら上書きする**。実写化は改善方向であり、ADR 00021 の「概念イメージを実写で上書きする」と同じ扱い。上書きされた生成アセットは Release に残るが参照されないだけで害はない

### 画像が無い残りの行は当面空欄とする

約56%の行は空欄のまま置く(scientist が象徴カード導入前に取っていた形)。全行を埋める案として **AI生成(ローカルSDXL)の画像**を採用予定で、生成方式の詳細は別 ADR で決める。対象の線引きを先に記録しておく:

- **概念語・器具・作品名など人物以外の行**: AI生成のイラストで埋めてよい
- **歴史上の人物**(卑弥呼など、肖像権・パブリシティ権の問題がない没後長い人物)で実写・史料画像が取れない行: **AI生成の「想像画」で埋めてよい**。教科書が卑弥呼の想像図を載せるのと同じ位置づけで、想像画・AI生成である旨を明示する
- **近現代の実在人物**には AI 生成の肖像を作らない。本人と誤認されるリスクが質的に違う(実写が取れない近現代人物はほぼ無く、実害も小さい)
- 生成画像は fictional(ADR 00006)と同じく GitHub Release で配布し、AI 生成である旨を明示する

## Consequences

- 検索を使わない完全一致方式なので、表記ゆれ(「は虫類」等)や教科書独自の言い回しの語は記事があっても引けないことがある。付与率より正しさを優先した結果として受け入れる
- リード画像は記事の代表画像であって「その語の教科書的な図」とは限らない(人物記事は肖像、概念記事は模式図が多く、実用上は十分)
- ja.wikipedia 側の記事・画像の追加で付与率は上がる。`tools/.cache/` にキャッシュされるため、引き直しは `--refresh` で行う
- 空欄の行が多いリストとして当面運用する。利用側で画像必須のビュー(動画のサムネイル等)は空欄行の扱いに注意

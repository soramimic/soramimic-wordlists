# ADR 00021: insect(昆虫)ワードリストの新規作成と自動更新

- Status: accepted
- Date: 2026-07-28
- Supersedes: none
- Superseded by: none
- Related: 00007(sekitsui の自動更新。本リストはその設計を昆虫に踏襲) / 00008(plant。目ごとの分割クエリと界ガードの前例) / 00014(既存行を劣化させない) / 00015(画像・分類補完を月次バッチに入れない扱い)

## Context

脊椎動物 sekitsui(ADR 00007)・植物 plant(ADR 00008)に続く生物リストとして、昆虫の和名リストを新設する。空耳の材料として昆虫の和名(カブトムシ・オニヤンマ・アメンボ…)は語感の幅が広く需要があるのに、既存リストには1件も入っていない(sekitsui は脊椎動物のみ、plant は植物のみ)。

sekitsui / plant と同じく `surface = pronunciation = カタカナ和名` の構造なので、人名リスト(ADR 00005)で必要な「記事冒頭文からの読み抽出」は不要で、Wikidata の日本語ラベルがそのまま答えになる。

昆虫は規模と分類の性質が既存2リストと違い、そのままでは踏襲できない点が3つある。

1. **Wikidata の昆虫 taxon が桁違いに多い**。コウチュウ目・チョウ目だけで数十万件あり、昆虫綱 Q1390 の一括クエリはもちろん、**目単位でもコウチュウ目 Q22671 は必ず WDQS がタイムアウトする**(実測: 504 が4回連続)。plant の「目ごとに分割」だけでは足りない
2. **目の一覧そのものが引けない**。plant の `?o wdt:P171* wd:<界> ; wdt:P105 wd:Q36602` に相当するクエリは、Blazegraph が昆虫綱側から降りる走査になりタイムアウトする
3. **目が30以上あって `class` 列の分類軸として細かすぎる**。sekitsui は5区分・plant は6区分だが、昆虫の目をそのまま使うと70区分になり、利用側の絞り込み軸として使いものにならない

加えて、**和名の同名異義が既存2リストより深刻**である。カマキリ(昆虫)は魚アユカケの別名でもあり(実際に PR #62 で sekitsui 側のカマキリを魚として確定させた経緯がある)、トンボ・セミ・ミノムシ・カミキリなども脊椎動物・植物と衝突する。

## Decision

Wikidata を出典に `tools/update_insect.py` の月次バッチで未収録の種を追記する。ADR 00001 の4基準(機械可読な構造化データ / 認証不要 / CC0 / 差分追記)を満たし、sekitsui / plant と同じ差分方式(既存行の表記・id は書き換えず、未収録の和名だけ id 連番で追記)を採る。

### 収録基準

- 対象は **昆虫綱 Insecta Q1390** 配下の **rank=種(Q7432)** で **日本語ラベルがカタカナのみ**の taxon。カタカナ以外(漢字ラベル、曖昧さ回避付き)は既存リストの性格に合わないので除外する(sekitsui / plant と同じ基準)
- 列は sekitsui.csv に揃える: `id, original, surface, pronunciation, class, extinct, order, family, image, image_page, wikidata`
- **化石種・絶滅種も含める**。判定は sekitsui / plant と同じで、IUCN ステータス(P141)が絶滅種(Q237350)/野生絶滅(Q239509)、または instance of(P31)が化石タクソン(Q23038290)のいずれか。`extinct` 列(yes/no)で区別する

### 非昆虫の節足動物は対象外にする

クモ・ダニ・サソリ(鋏角亜門)、ムカデ・ヤスデ(多足亜門)、エビ・カニ・ダンゴムシ(甲殻類)は**収録しない**。理由は次の3つ。

- **リストの意味が曖昧になる**。「昆虫」は日常語としても分類群としても昆虫綱を指すので、クモを混ぜると利用側で「昆虫リストにクモが入っている」という不整合になる。sekitsui が脊椎動物 Q25241、plant が植物界 Q756 と単一のルートで定義されているのと揃える
- **class 区分が破綻する**。下記の大分類は昆虫の目を束ねたものなので、非昆虫を入れると全部「その他」に落ちて分類軸として機能しない
- **取得の分割方法が使えない**。本リストの取得は「昆虫綱から目まで降りて目ごとに引く」設計で、鋏角亜門・多足亜門は別の階層構造を持つ

将来まとめて欲しくなったら、同じ設計で `arthropod.csv`(または `mushi.csv`)を別に作る。ルートを節足動物門 Q1360 にして昆虫綱を除外すれば、本リストと重複しない補集合として作れる。

### class 列は「目をまとめた粗い区分」にする

昆虫の目は Wikidata で70件(化石のみの目を含む)あり、そのままでは分類軸にならない。**種数と知名度がともに大きい現生7目だけを個別の区分に立て、残りをすべて「その他」にまとめる**。

| class | 対応する目 | QID | 初回収録数 |
|---|---|---|---|
| チョウ | チョウ目 Lepidoptera(ガを含む) | Q28319 | 656 |
| 甲虫 | コウチュウ目 Coleoptera | Q22671 | 593 |
| カメムシ | カメムシ目 Hemiptera(セミ・アブラムシを含む) | Q26371 | 210 |
| ハチ | ハチ目 Hymenoptera(アリを含む) | Q22651 | 144 |
| トンボ | トンボ目 Odonata | Q25375 | 97 |
| バッタ | バッタ目 Orthoptera(コオロギ・キリギリスを含む) | Q167810 | 97 |
| その他 | 上記以外のすべての目(カマキリ目・ゴキブリ目・ナナフシ目・カゲロウ目・化石の目 など) | — | 97 |
| ハエ | ハエ目 Diptera(カ・アブを含む) | Q25312 | 86 |
| NA | 昆虫綱の配下だが目が引けなかった行の受け皿(初回は0行) | — | 0 |

初回生成(2026-07-28)は計 **1,980 種**。sekitsui(16,709)・plant(6,541)より小さいが、これは Wikidata 側で日本語ラベルを持つ昆虫 taxon が世界の記載種100万種超に対して数千件しかないためで、取得の取りこぼしではない。

- 区分名は目の和名(コウチュウ目)ではなく通称(甲虫)にする。空耳の利用側では「甲虫」「チョウ」の方が直感的で、`class~=チョウ` のような絞り込みが自然になる
- **7目の選定基準は「Wikidata のカタカナ和名の実測件数」と「日常的な知名度」の両方**。この7目でカタカナ和名の大半を占める。カマキリ目(18)・ゴキブリ目(32)・ナナフシ目(9)は知名度が高いが件数が2桁で、区分を増やすほど概念イメージの枚数も増えるため「その他」(計97)に含める
- 区分の判定は**取得クエリの起点になった目**で行う。系統樹の重複で同じ和名が複数の対象から引けたときは、上表の7目を先に引くことで決定的に7目側を優先する

### 取得の分割: 昆虫綱から下向きに辿り、失敗したら再帰的に割る

- **目の一覧は昆虫綱から P171 の子を1段ずつ下向きに幅優先で辿って集める**。`?o wdt:P171* wd:Q1390 ; wdt:P105 wd:Q36602` はタイムアウトするので使えない。rank=目 に達したらそこが取得対象。結果は `tools/.cache/insect_orders.json` に保存する(`--refresh` で引き直し)
- **Wikidata の昆虫は階級付けが一貫していない**ことに注意する。ゴキブリ目 Blattodea Q25309 は「亜目」、シロアリ Isoptera Q546583 は epifamily になっており、rank=目 だけを打ち切り点にすると、その配下を目より下まで展開してクエリ数が爆発する。そこで**目より下の階級(亜目・下目・上科・科・亜科・族・属・種…)に達した枝も打ち切り、その地点自体を取得対象に加える**。取りこぼしは起きず、class は「その他」になる。無階級のクレード(rank が空、または Q713623 clade)は打ち切らずに展開する
- **コウチュウ目 Q22671 は目単位でもタイムアウトする**。取得に失敗した対象は自動的に直接の子タクソンへ**再帰的に分割**する(最大5段)。待っても通らないクエリなので WDQS のリトライは1回で打ち切る(`wpnames.sparql(retries=1)`)。この再帰分割があるので、将来ほかの目が巨大化しても運用は変わらない
- 取得総数が下限(`MIN_TOTAL` = 1,500)を下回ったら取得失敗とみなして中断する(sekitsui の 5,000 / plant の 4,000 と同じ妥当性ガード)。実測 1,980 に対し、チョウ目かコウチュウ目が丸ごと落ちたら下回る水準に置いた

### order / family は上位タクソンを辿って付ける

- `order`(目)・`family`(科)の和名は、収集した taxon QID を種として `tools/taxonomy.py`(sekitsui の目・科、plant の科・属と共通)で P171 方向に1段ずつ辿って求める。階級付きの日本語別名(「トンボ目」)があればそれ、無ければ日本語ラベル、無ければ学名(P225)。引けなければ空にする
- **和名からの逆引きはしない**。plant が「スギ・ハス等で動物側のタクソンを拾う」ため QID がある行だけを対象にしたのと同じ理由で、昆虫でも和名から引くとカマキリ(魚)の科を拾ってしまう。update_insect.py は取得時に taxon QID を保持しているので、その QID を起点に辿る
- sekitsui / plant では目・科の補完を別スクリプト(`enrich_*_taxonomy.py`)に切り出して月次バッチから外している(ADR 00015 / 00017)が、**insect は updater 本体に含める**。対象が数千件と小さく、追加の所要時間が数分にとどまるため、別スクリプト化する利点がない

### 同名異義(homonym)対策は2段構え

1. **クエリの起点を昆虫綱側に閉じる**(plant と同じ一次対策)。取得は必ず `?t wdt:P171* wd:<昆虫側の目>` で引くので、和名で名寄せしても魚アユカケ(カマキリ)や植物の taxon が候補に入らない。「和名から QID を引いてから綱を判定する」順序にすると、同名の魚を先に拾って昆虫の行に魚の写真・科を付けてしまう
2. **書き込み直前に上位タクソンで再確認する**。新規追加候補の taxon QID について `?t wdt:P171* ?a` で上位を列挙し、**昆虫綱 Q1390 に到達する**ものだけを採用する(`screen_taxa`)。判定を Python 側で行うのは、`?t wdt:P171* wd:Q1390` と直接書くと Blazegraph が昆虫綱側から降りる走査になりタイムアウトするため

**plant の動物界ガードをそのまま裏返してはいけない**。plant は「候補が動物界 Q729 に到達したら落とす」で正しく効くが、昆虫で「脊椎動物 Q25241 / 植物界 Q756 に到達したら落とす」にすると**本物の昆虫を落とす**。実例はまさに ADR 00014 が plant 側の混入元として挙げたヘビトンボ Protohermes grandis(Q2481303)で、これは Corydalidae → ヘビトンボ目 → 昆虫綱と正しく繋がっている本物の昆虫でありながら、Wikidata に Papaveraceae → キンポウゲ目 → 植物界 という誤った親も同時に付いている。同じ1本の誤リンクが、plant 側では「植物に混じった昆虫」(落とすのが正しい)、insect 側では「余計な親が付いた本物の昆虫」(残すのが正しい)として現れる。

「昆虫綱にも植物界にも到達する」という条件だけでは、この2つ(本物の昆虫に余計な親が付いた場合と、非昆虫が昆虫の配下に誤リンクされた場合)を区別できない。そこで**界をまたぐ taxon は自動で落とさず、実行ログに一覧を出して人(またはエージェント)の判断に回す**。実体が昆虫でなければ `EXCLUDED` に足す。初回生成(2026-07-28)でこの報告に出たのはヘビトンボ1件だけで、実体は昆虫なのでそのまま収録した。

**和名が昆虫と脊椎動物・植物で同音異義になっているだけの行は、両方のリストに残す**。カマキリは昆虫綱に taxon が実在するので昆虫の和名として正しく、sekitsui 側のカマキリ(アユカケの別名)も魚の和名として正しい。空耳の材料としてはどちらも使えるので、重複は実害にならない。

上の2段をすり抜ける混入(昆虫の taxon に非昆虫の日本語ラベルが誤って付いている等)は、plant / scientist / youtuber と同型の `EXCLUDED`(和名の恒久除外リスト。除外理由をコメントで併記)で落とす。CSV から消すだけでは翌回の自動更新で再追加されるため。**ラベル改名等で除外が効かなくなったら実行ログに「EXCLUDED に未ヒットの項目」として出す**(再混入に気付けるように)。初回時点では該当が無いので空集合で始める。

### 既存行は劣化させない(ADR 00014)

初回から ADR 00014 の原則を守る。

- `class` / `order` / `family` は**今回の取得で実データが取れたときだけ**更新する。分割クエリの取りこぼしや Wikidata 側のラベル改名で当回の結果から名前が落ちても、既存値(NA・空を含む)を保つ
- `extinct` は `no` → `yes` の一方向のみ更新する。絶滅シグナル(P141・P31)は取りこぼしやすく、取りこぼしで `yes` → `no` に落とすと情報が失われる
- 実行ログに「既存の分類不明(NA)」「今回未取得だが既存分類を保持」の件数を出す

### 画像(image / image_page / wikidata)

sekitsui(ADR 00007 / 00015)・plant(ADR 00008)と同じく、Wikidata の P18(画像)から Wikimedia Commons の写真を付与する。付与は `tools/enrich_insect_images.py`。

- 取得の起点・分割・混入ガードは `update_insect.py` と完全に共通のものを import して使う(同名異義ガードを「クエリの起点」で効かせる方針を画像側でも守るため)
- `wikidata` 列には画像の取得元になった taxon の QID を入れる。sekitsui / plant と同じく画像とセットで埋まる列とし、画像が取れなかった行は3列とも空のままにする
- **月次バッチには入れず手動実行とする**(ADR 00015 / 00008 と同じ扱い)。取得対象が170件超あり、コウチュウ目の再帰分割を含めて全体で60分前後かかる。月次で増える新規種は数十件規模なので、画像はまとめて手動で補完すれば足りる
- 付与率は初回実行(2026-07-28)で **1,420/1,980 行 = 71.7%**(sekitsui 83% / plant 88.6% より低い)。昆虫は種数の割に Commons の種同定済み写真が少なく、Wikidata の P18 が未設定な taxon が多いためで、異常ではない。妥当性ガード(`MIN_TOTAL` = 800)はこの実測値を基準に置く
- 対象ごとの取得結果は `tools/.cache/`(Git 管理外)に逐次保存し、中断しても再実行で続きから再開できるようにする(全件引き直しは `--refresh`)

### 実写が取れない行には「分類レベルの概念イメージ」を割り当てる

sekitsui(ADR 00007)・plant(ADR 00008)と**同じ仕組みをそのまま使う**。`class` 列の単位で1枚ずつ概念イメージを作り、実写が無い行に共有で割り当てる。

- **これは「その種の姿」ではなく「その区分のイメージ」**なので、実写と誤認されないよう**画像の右上に「イメージ」と明記**する。特定の種は描かず、その区分を代表する記号的な絵にする(甲虫=背面から見た上翅が割れた楕円形の体 / チョウ=左右2対の翅とこん棒状の触角 / ハチ=縞のある腹部とくびれた腰 / ハエ=大きな複眼と横に張り出した翅 / カメムシ=盾形の体と逆三角形の小楯板 / バッタ=くの字に折れた太い後脚 / トンボ=4枚の細長い翅と長い腹部 / その他=頭・胸・腹の3部と6本脚という昆虫一般の姿)
- 画像は sekitsui / plant と同じ `tools/gen_class_images.py`(自己完結SVG・320x200)で生成する。昆虫用のシルエットと配色は同じ定義テーブル(`GROUPS` / `PALETTES` / `SHAPES`)に置く。左右対称の図が多いので、片側だけ書いて鏡像コピーする `_both()` を足した。8区分を見分けやすくするため配色を4つ(amber / plum / slate / rust)追加した
- **配布は既存の `class-image-v1` リリースにアセットを追加する形にし、新しいタグは切らない**。タグは「絵柄のバージョン」を表すものであってリスト単位ではなく、アセットの追加は既存URLを一切変えない(sekitsui の6枚・plant の6枚はそのまま)。分類不明用の `class_unknown.svg` は3リストで共用する
- 割り当ては共通の `tools/apply_class_images.py`(`TARGETS` に insect を追加、ネットワークアクセス無し)。**`image` が空の行だけ**に設定し、実写がある 1,420 行は触らない。冪等。初回は 560 行(甲虫278 / チョウ104 / カメムシ58 / ハチ38 / ハエ30 / その他24 / バッタ23 / トンボ5)に付与した
- **月次バッチには sekitsui / plant と同じ1ステップで入れる**。画像付与本体は重いので月次バッチ対象外(上記)だが、概念イメージの割り当てはオフラインで一瞬なので入れられる。これにより `update_insect.py` が追記した新規行にもその回で画像が付く
- **実写が後から取れたら概念イメージを上書きする**。概念イメージ→実写は改善方向であり、ADR 00014 の「既存行を劣化させない」に反しない

## Consequences

- insect が pokemon / nations / stations / baseball / football / scientist / sekitsui / plant / youtuber に続く自動更新対象になる
- **カマキリ・トンボ・セミ等が sekitsui / plant と同じ和名で重複する**。利用側が全リストを合成すると同じ表層が複数出るが、空耳の材料としては問題にならない。分類の正しさはリストごとに閉じている
- カマキリ目・ゴキブリ目・ナナフシ目のような知名度の高い群が `class=その他` になる。区分を増やしたくなったら `CLASS_BY_ORDER` に目を足し、`gen_class_images.py` に絵を1枚足して Release にアセットを追加すればよい(既存URLは変わらない)
- **Wikidata の昆虫は日本語ラベルの整備が種数の割に薄い**。世界の記載種100万種超に対しカタカナ和名を持つ rank=種 は数千件にとどまる。網羅リストへの追記運用なので、Wikidata 側の整備が進めば月次バッチで自動的に増える
- コウチュウ目の再帰分割はクエリ数が多く、`update_insect.py` の1回の実行が月次バッチの中で最も長いステップになる(30〜60分)。`continue-on-error` で独立させてあるので、タイムアウトしても他のリストは更新される。失敗時は insect.csv を巻き戻す
- 目の階級付けの揺れ(ゴキブリ目が亜目扱い等)は Wikidata 側の編集で変わりうる。変わった場合も「目より下の階級はすべて打ち切り点にする」設計なので取りこぼしは起きず、class が「その他」から正しい区分に変わるだけになる
- 追記のみで、既存の和名の削除・改名の反映はしない(網羅リストへの追記として運用)。ラベル改名は「旧名を残したまま新名を追記する」形になる(ADR 00014)
- 画像は「実写(Wikimedia Commons)」と「区分の概念イメージ(本リポジトリの Release)」が混在し、全行に画像が付いた状態になる。実写だけを使いたい利用側は `.../releases/download/class-image-` で始まる URL を除外できる
- 既に混入している行は自動では消えない(ガードは新規候補にしか効かない)。全量の棚卸しは `tools/audit_taxa.py insect`(ルート = 昆虫綱 Q1390)で行う

# ADR 00052: 名字の公式Web裏付けを全件ログ付きバッチで進める

- Status: accepted
- Date: 2026-08-13
- Supersedes: none
- Superseded by: none
- Related: 00014 / 00038 / 00050 / 00051

## Context

ADR 00051では公式人物ページを根拠にできる台帳を用意したが、初回は個別に約20候補を
探索しただけで、未確認行を広範囲に検索したとはいえなかった。未確認は7万組を超えるため、
検索エンジンや各サイトへ集中アクセスせず、数百件ずつ調査を積み上げる必要がある。

正例だけを保存すると、何を検索済みか分からず、見つからなかった候補を毎回検索してしまう。
一方、別読みの人物が見つかっても候補読みが存在しない証明にはならない。

## Decision

`tools/audit_myoji_official_web.py` で調査時点の候補をCSVへ固定し、各候補につき必ず1件の
検索結果をJSONLへ記録する。対象は、実在の可能性と利用価値を優先して次の条件を満たす行を
`rank`、`id`、読みの順に選ぶ。

- `verified=no`
- 順位がある
- JMnedictのsurnameエントリにも一致する

検索ログの状態は次の3つに限る。

- `verified`: 公式ページで同一人物の姓表記と読みを確認
- `no_support_found`: 検索したが条件を満たす公式ページを発見できず
- `ambiguous`: 検索結果はあるが同一人物への対応や読みを確定できず

`no_support_found` と `ambiguous` は非実在・誤読を意味せず、`verified=no`のままにする。
検索語、検索日、短いメモを全件に残す。正例だけはHTTPS URL、公式ソース種別、ページ表題、
掲載表記・読み、確認箇所も必須とする。ページ本文や名簿は保存しない。

検証器は候補の欠落・重複・取り違え、未確認行へのURL混入、正例の表記読み不一致を拒否する。
全件完了後、`promote`で正例だけを既存の `myoji_official_evidence.jsonl` へ移す。
次の日付で候補を準備するときは、過去の全検索ログに登場した表記・読みを除外し、未調査の
続きだけを選ぶ。候補スナップショットは上書きを拒否し、調査中に対象がずれないようにする。
同日に複数回進める場合は `2026-08-13-2` のように日付へ短いsuffixを付ける。

2026-08-13の初回本格バッチは上位225件を3分割し、公式機関、大学・病院、専門団体、
競技団体・チーム、企業の公式人物ページを検索対象とした。全225件に検索ログを残し、
8件で完全一致を確認、217件は条件を満たす公式ページを発見できなかった。正例は大学、
自治体、内閣府、公式競技団体のPDFでも再確認し、8件すべてを `official_web` へ昇格した。

同日の第2バッチは、初回の225件を自動除外した次の300件を3分割して調査した。4件で
完全一致を確認し、296件は条件を満たす公式ページを発見できなかった。第2バッチの正例は
日本オリンピック委員会、KEIRIN.JP、K-1、日本小児科学会の公式ページで再確認した。
累計の調査済みは525件、`official_web`へ昇格した正例は初回からの合計12件となった。

2026-08-14の第3バッチは、高優先度母集団に残った224件をすべて調査した。16件で完全一致を
確認し、208件は条件を満たす公式ページを発見できなかった。検索担当の正例候補18件を
独立再監査し、実際の読みが濁音違いだった1件と、根拠URLが消滅して再現不能だった1件を
除外した。この完了により、`verified=no`・順位あり・JMnedict一致だった749件は全件検索済み、
うち28件を `official_web`へ昇格した。既存の個別確認1件と合わせ、公式Web根拠は29件になった。

続いてJMnedict一致条件を外し、順位だけがある未確認366件を全件調査した。7件で完全一致を
確認し、359件は条件を満たす公式ページを発見できなかった。これにより、順位付きの未確認
候補1,115件は全件検索済みとなり、バッチから35件、先行個別確認を含め36件に
`official_web`根拠が付いた。

順位付き候補の完了後、順位なし・JMnedict一致の第1バッチ600件を調査した。6件で完全一致を
確認し、594件は条件を満たす公式ページを発見できなかった。希少姓・異体字が多い層なので、
公式ページの表記がCSV候補と完全一致する場合だけ採用した。累計検索数は1,715件、
バッチ正例41件、先行個別確認を含む公式Web根拠は42件となった。

同じ母集団の第2バッチ600件を調査し、6件で完全一致を確認、594件は条件を満たす公式
ページを発見できなかった。累計検索数は2,315件、バッチ正例47件、先行個別確認を含む
公式Web根拠は48件となった。

第3バッチは処理単位を900件に増やして調査し、2件で完全一致を確認、898件は条件を満たす
公式ページを発見できなかった。検索時には完全一致したが公開URLが消滅して再現できなかった
1件は採用しなかった。累計検索数は3,215件、バッチ正例49件、先行個別確認を含む
公式Web根拠は50件となった。

## Consequences

- 正例が少なくても、実際に何件を調査したか監査でき、次回は続きから始められる
- 検索エンジンの要約だけで採用せず、最終ページを開いて同一人物への対応を確認する
- 公式サイトであっても利用条件、robots、レート制限を守り、認証回避や大量クロールをしない
- 検索時点で見つからなかった情報は後日公開されうるため、必要なら日付を変えた再調査
  バッチとして追加する

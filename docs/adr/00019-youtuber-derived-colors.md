# ADR 00019: 象徴カードの配色を公式ポートレートの情報解析で拡充する

- Status: accepted
- Date: 2026-07-28
- Supersedes: [00018](00018-youtuber-images.md) (Decision 5 のうち「イラスト/アバターからのパレット抽出はしない」という判断のみ)
- Superseded by: none

## Context

ADR 00018 で youtuber.csv の実写が取れない712人に「象徴カード」SVGを割り当て、配色には
**公式が公表しているイメージカラー**を使うことにした。しかし色が付いたのは68人だけで、
残り644人は `category` と `org` のハッシュ由来の機械的な配色のままである。とくに
にじさんじ勢は43人が全員ほぼ同じ色相になり、「誰のカードか」が伝わらない。

ADR 00018 は色の取得元を「公式がテキストで書いた色」と「ペンライトカラー一覧画像」に限り、
**イラストからのパレット抽出は「表現に依拠している疑いが残る」として避けた**。この判断は
著作権法の条文に照らすと過度に保守的だった。

## Decision

### 1. ポートレート画像の情報解析で代表色を求めてよい(著作権法30条の4)

著作権法30条の4は、著作物を**情報解析**(多数の著作物その他の大量の情報から、当該情報を
構成する言語・音・影像その他の要素に係る情報を抽出し、比較、分類その他の解析を行うこと)の
用に供する場合、**その著作物に表現された思想又は感情を自ら享受し又は他人に享受させることを
目的としない限り**、必要と認められる限度で利用できると定める。

- 画像を画素の集合として統計処理し、面積比の大きい色を求めるのは、条文がいう情報解析である
- 出力は16進値が最大2つ。**元の表現との実質的類似性を持たない**ので、複製にも翻案にもならない
- カードは配色と文字だけの自作SVGのままで、イラストを見せる目的がない(享受目的ではない)

よって、**解析を目的とした取得・処理は問題ない**。ADR 00018 が置いた「イラストからは色を
採らない」という線引きは撤回する。かわりに次の制約を守る。

- **取得画像を再配布しない**。`tools/.cache/`(Git管理外)止まりで、リポジトリには置かない
- カードは引き続き**自作SVG(色と文字のみ)**。イラストの貼り込み・トレースはしない
- 出力する色は**最大2色**。細かいパレットを再現しない(パレットそのものを配布する形にしない)
- 出典(メンバーページのURL)を必ず記録する
- **公式が色そのものを公表している人は公式値を優先**し、解析値で上書きしない

### 2. 解析の対象は VTuber に限る

ポートレートが**デザインされたキャラクタービジュアル**である人(VTuber)は、髪・衣装の
主要色がそのまま「その人の色」として通じる。一方、実在YouTuberの宣材写真から色を採ると
肌・黒髪・背景しか出ず、全員が似た茶褐色になって情報量が増えない。カード対象の実在
YouTuber(463人)は従来どおり `category` + `org` のフォールバック配色のままにする。

### 3. 取得元は事務所の公式メンバー一覧ページ

`tools/derive_youtuber_colors.py` に事務所ごとのアダプタを並べる。人物と画像の対応づけは
既存の色取得(`fetch_youtuber_colors.py`)と同じく、**ページに書かれた日本語名を空白除去して
`original` と完全一致させる**方式にする。

- 同じ名前が**複数の事務所ページ**に出てきたら、取り違えを避けるため**捨てる**
- ページ側にいて youtuber.csv に居ない人は保存しない(メンバー一覧を丸ごと複製しない)
- 1件も取れなくなったソースはエラーにする(黙って0件になると色が静かに消える)

### 4. 抽出は「背景を落として、彩度の高い領域から2色」

1. 画像を長辺160pxに縮小する。以降の処理はすべて決定的で、同じ画像からは毎回同じ色が出る
2. **背景を落とす**。アルファがあれば透明部分、無ければ画像の縁からフラッドフィルする。
   「隣の画素と近ければ背景を広げる」ので、単色ベタにもグラデーションにも追随し、
   キャラクターの輪郭線で止まる。内側にある白(白髪など)は残る
3. 画素に重みを付ける。**彩度が高いほど重く**し、**肌色帯・線画の黒・ハイライトの白**は軽くする
4. CIELAB空間で重み付きk-means(k=6、決定的な初期化)
5. クラスタの代表色は**平均ではなく最頻色**にする。平均だと「明るい髪+その影」が混ざって、
   画面のどこにも無いくすんだ色になる
6. **肌のクラスタは主色・副色の候補から外す**。重みを下げるだけでは、顔アップの
   ポートレートで肌が勝ってしまうことがある
7. 面積比の大きいクラスタを主色、そこから ΔE00 で 22 以上離れた2番目を副色にする

### 5. `source` は `derived-portrait` にして公式値と区別する

`tools/youtuber_colors.json` の `source` に `derived-portrait` を使い、`source_url` に
メンバー一覧ページのURLを入れる。利用側は「公式が公表した色」と「解析で求めた色」を
区別できる。カード生成側(`gen_youtuber_cards.py`)は両者を同じように扱う。

## Consequences

- 色が付く人が **68人 → 109人**(カード対象712人のうち)に増える。内訳は
  にじさんじ36・ホロライブ3・HOLOSTARS1・その他1(残りは公式色を優先した68人)。
  にじさんじ勢が全員同系色だった状態は解消される
- **手法の妥当性は公式色が既知の68人に同じ抽出をかけて裏取りした**(`--validate`)。
  公式値には性質の違う2種類が混ざるので分けて評価する
  - `official`(公式サイトがテキストで書いている色。キャラクターデザインから決まった連続値)
    n=16 に対して ΔE00 は**主色だけで中央値15.4、2色のうち近い方で中央値12.3**
    (ΔE00≦20 が 13/16)。ぶいすぽっ！の花芽すみれは公式値 `#beccff` に対して抽出も
    `#beccff` で完全一致した。あおぎり高校の我部りえる 4.7、Neo-Porteの胡桃のあ 5.2 と続く
  - `official-penlight`(12色の離散パレット。RED=`#ff0100` など)n=52 に対しては
    主色で中央値26.4、2色のうち近い方で中央値19.5 と大きく出る。**イラストの中にその色が
    literally 存在しない**ためで、色差の絶対値は指標にならない。色相の系統(赤/橙/黄/緑/
    青/紫/桃/白)で見ると**抽出した2色のどちらかが公式色と同じ系統に落ちるのは 30/52(58%)**。
    さくらみこ=LIGHT PINK に `#eb3c69`(桃)、火威青=BLUE に `#4e5d77`(青)、
    星街すいせい=BLUE に `#252675`(青)と、狙いどおりの系統が出ている
  - 系統が外れる22人は、ペンライトカラーが「そのライブでの割り当て」で、髪や衣装の面積では
    なく**アクセント色**を指しているものが多い(大神ミオ=GREEN・角巻わため=YELLOW・
    ときのそら=BLUE)。面積比で採る本手法とは原理的にずれるので、これは受け入れる。
    白系(白上フブキ・獅白ぼたん・白銀ノエル)は、髪が白でも影と線画を含めた面積では
    暗い色が勝つため無彩色側に寄る
- **取り違えの検出**は次の4段で行う
  1. 名前は空白を除いた**完全一致**のみを採る(部分一致・別名解決はしない)
  2. 同じ名前が複数の事務所ページに出てきたら警告して捨てる
  3. `--validate` は「その人の公式色」と「その人のポートレートから採った色」を突き合わせる
     ので、**人と画像がずれていれば ΔE00 が全体的に跳ね上がる**。実測では公式値が
     連続値の16人で中央値12.3 に収まっており、系統的なずれは無い
  4. `--swatches` で抽出色の一覧をHTMLに出し、名前と色を目視で突き合わせられる
- 事務所サイトのHTML構造に依存するので、改修で取れなくなりうる。1件も取れなかったソースは
  エラーにしてある。にじさんじは卒業したライバーが一覧から消えるため、7人は埋まらない
- 実在YouTuber463人は従来のフォールバック配色のままで、ここは今回変わらない
- 月次バッチには入れない。画像の取得と解析に時間がかかるので手動実行の運用にする

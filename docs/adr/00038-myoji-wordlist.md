# ADR 00038: myoji(名字)ワードリストの新規作成と、世帯数を収録しない判断

- Status: accepted
- Date: 2026-08-02
- Supersedes: none
- Superseded by: none
- Related: 00001(自動更新のソース選定4基準) / 00005(人名リストの自動更新) / 00009(description の生成方式) / 00014(既存行を劣化させない) / 00030(時変値を毎回全行上書きする先例)

## Context

空耳の材料として日本の名字は使いどころが多いのに、既存リストには「実在の人物名」(baseball / football / scientist / youtuber)の姓が付随的に入っているだけで、名字そのものを網羅したリストが無い。読み(カタカナ)付きで数万件の名字を持てば、姓だけの空耳・人名の合成に使える。

名字リストを作るときに普通に欲しくなるのは **世帯数・人口順位**(「佐藤は約180万人で1位」)だが、これがそのままでは手に入らない。

- **日本には姓別の公的統計が存在しない**。国勢調査は姓を集計していないので、政府統計としての「名字ランキング」は無い
- 世帯数・順位を公開しているのは民間サイト(名字由来net、日本の苗字七千傑など)だけで、**いずれも利用規約でスクレイピング・データの再配布を明確に禁止している**。GitHub 上に出回っている非公式CSV(`siikamiika/japanese-family-names` など)はこれらのサイトのデータの複製であり、元サイトが再配布を禁じている以上、ライセンス上使えるようにはならない
- 電話帳・住宅地図由来のデータも同じく第三者の著作物・データベースであり、基準 3(再配布・クレジット表記が満たせること。ADR 00001)を満たさない

つまり「世帯数の入った名字リスト」は、このリポジトリのライセンス方針では作れない。作れないものを諦めるか、別の軸で「よく見る名字が上に来る」性質を再現するかの判断が要る。

## Decision

**世帯数・人口順位は収録しない。** 代わりに、母集団・読み・順位・説明をすべて再配布可能なソースだけで組み立てた `myoji.csv` を新設し、`tools/update_myoji.py` の月次バッチで更新する。禁止ソース(名字由来net / 日本の苗字七千傑、およびそれらを複製した非公式CSV)は**一切参照しない**。

列は `id, original, surface, pronunciation, rank, description, wikidata`。

### 母集団と読みは SudachiDict(Apache-2.0)から採る

形態素解析用辞書 [SudachiDict](https://github.com/WorksApplications/SudachiDict)(Works Applications、**Apache License 2.0**)の辞書ソース `small_lex.csv` / `core_lex.csv` / `notcore_lex.csv` から、品詞が `名詞,固有名詞,人名,姓` のエントリを抜く。表記と読み(カタカナ)が対で入っているので、**読みを推定せずに済む**のが決め手。

- **辞書ソースCSVは GitHub には無い**。git-lfs から離れて S3 配布(`https://sudachi.s3-ap-northeast-1.amazonaws.com/sudachidict-raw/<YYYYMMDD>/*_lex.zip`)になっており、リポジトリの `src/main/text/` には `synonyms.txt` しか残っていない。updater はバケットの一覧から最新バージョンを選んで取得する
- **ライセンス**: 配布物全体が Apache License 2.0。同梱の `LEGAL` に、`small_lex.csv` が UniDic(BSD 3条項。The UniDic Consortium)を、`core_lex.csv` / `notcore_lex.csv` が [mecab-unidic-NEologd](https://github.com/neologd/mecab-unidic-neologd)(Apache-2.0。はてなキーワード一覧・日本郵便の郵便番号データ・スナフキん氏の日本全国駅名一覧・工藤拓氏の人名(姓/名)エントリデータを素材とする)を含むことが記されている。**名字の大半はこの「工藤拓氏の人名エントリデータ」(Mozc の人名辞書由来)に遡る**。いずれも再配布可能で、README の出典欄に帰属を書く
- 初回生成(2026-08-02)は SudachiDict **20260723** を使用
- **ノイズ除去は最小限にする**。このリポジトリの方針は「広く収録してフラグで絞る」なので、明確なゴミだけを落とす
  - ローマ字見出し(`Yamada` `ENDO` など46件)を落とす。同じ名字の別表記でしかない
  - かな書きだけの見出し(`いしはら` `クロサワ` など1,367件)を落とす。漢字表記の行と重複し、`original` を漢字表記とする列設計に合わない
  - 読みがカタカナでない行・表記が9文字以上の行を落とす(実測の最大は5文字)
  - **1文字の名字は落とさない**。林・東・原・森のように実在する

### rank は「著名人ベースの参考順位」であって世帯数ではない

Wikidata(CC0)の **日本国籍の人物**(`wdt:P31 wd:Q5` かつ `wdt:P27 wd:Q17`)の **姓**(`wdt:P734`)を数え、人数の多い順に 1 位から順位を振る。同数は同順位(1, 2, 2, 4…)。集計に出てこない名字は空。

- **QID ではなく日本語ラベルの文字列で名寄せして合算する**。Wikidata には同じ名字の項目が複数あり(「佐藤」だけで6項目)、QID 単位で数えると同じ名字の人数がばらける
- 集計の規模(2026-08-02 時点): 日本国籍の人物 257,783人のうち、姓(P734)が設定されているのは **125,643人**(48.7%)。うち日本語ラベルを持つ姓に紐づく **125,507人** を 9,085 種の姓ラベルに集計した。上位は 田中(1,971) 佐藤(1,797) 高橋(1,712) 鈴木(1,514) 小林(1,437) で、**世間で知られている多い名字の並びとおおむね一致する**ので、参考順位として使える水準にある
- **ja.wikipedia の記事タイトルから姓を機械抽出する案は採らなかった**。Wikidata の P734 で十分な規模(12万人)が取れ、記事タイトルの姓名分割という誤りやすい処理を挟まずに済み、かつ CC0 なので出典表記の制約も軽いため
- **この rank は人口順位ではない**。次の歪みを最初から含んでいる
  - 分母が「Wikidata に人物項目のある著名人」なので、芸名・筆名・力士の四股名が実在の名字と同じ重みで数えられる
  - Wikidata 側の整備度に依存する(P734 が付いているのは日本国籍の人物の約半分)
  - 同じ名字がかな表記の項目(「むとう」76人)と漢字表記の項目(「武藤」47人)に分かれることがあり、かな表記だけの姓ラベルが延べ 3,284人(全体の 2.6%)ある。これらは漢字の `original` と一致しないので rank に反映されない
  - 異体字が別ラベルになる(「高野」149人 / 「髙野」21人)
  - よって**順位の絶対値には意味を持たせず、「よく見る名字を上から取る」程度の目安として使う**。CSV の列説明・README・本 ADR にその旨を明記する
- **rank は毎回全行を再計算して上書きする**。これは「既存行を劣化させない」(ADR 00014)の**明示的な例外**で、youtuber の `subscribers`(ADR 00030)と同じ扱い。順位は集計のスナップショットなので、一部の行だけ更新すると同じ列の中で基準時点が混ざり、順位として読めなくなるため

### description は ja.wikipedia の姓記事から採り、「◯◯氏」を優先する

由来・分布のトリビアは ja.wikipedia の姓記事(CC BY-SA 4.0)の冒頭から、`tools/wpnames.py` の `make_description`(scientist / youtuber と共通。「。」区切りの完結文を目安90字まで連結し、常に「。」で終わる)で作る。

ここで**素直に「表記と同じタイトルの記事」を引くと失敗する**。「佐藤」「鈴木」「高橋」「田中」の ja.wikipedia 記事は**人物の曖昧さ回避ページ**で、冒頭が「佐藤（さとう）」だけしかない。Wikidata 側でもこれらの記事は曖昧さ回避ページ(Q4167410)として型付けされており、姓の概念項目(佐藤 = Q978692)には ja サイトリンクが無い。つまり **`?item wdt:P31/wdt:P279* wd:Q101352` + ja サイトリンクという引き方では、日本で最も多い名字が丸ごと落ちる**(実測 776件しか当たらず、うち辞書と表記が一致するのは275件)。

そこで次の順に採る。

1. **姓そのものを説明している記事名を優先順に試す**: `{表記} (姓)` → `{表記} (名字)` → `{表記}氏` → `{表記}家` → `{表記}`。曖昧さ回避サフィックス付きの記事がいちばん姓そのものの説明で、次が氏族記事。「佐藤氏」「鈴木氏」「高橋氏」「田中氏」「中村氏」はいずれも由来・分布がきちんと書かれている(例: 鈴木氏 →「日本の氏族で 代表的な名字のひとつ。祭礼の際に祭られる稲穂や神社の本坪鈴に由来した神職の姓氏とされる。」)
2. 候補は表記あたり5件になるので、**先に記事の存在確認(1リクエスト50件)で絞ってから冒頭文(1リクエスト20件)を取る**。全候補に冒頭文を投げると問い合わせが5倍になるため
3. `{表記}` の素の記事は曖昧さ回避ページが大半なので、**説明文に姓の語(姓 / 名字 / 苗字 / 氏族)が含まれるものだけ**採る(サフィックス付き・氏族記事は表題からして姓の説明なのでこの縛りは掛けない)
4. **「〜を参照のこと。」「詳細は〜」だけの誘導文は採らない**。「東郷」の記事は誘導文だけで情報が無く、そのまま採ると中身の無い description になる。`参照` `詳細は` を含む文を落としてから組み立て、残りが12文字未満なら不採用にする
5. **由来・分布の文を優先して拾う**。ユーザーが期待しているのは「どこに多いか・由来」なので、`由来` `発祥` `起源` `に多い` `分布` を含む段落を優先して選び、90字の説明にこれらの語が入らなかった場合は、後ろの文から該当する1文だけを足す(全体130字まで)
6. **曖昧さ回避の箇条書き(「上杉氏（うえすぎし） - 室町時代の…」のような ` - ` を含む行)と、12文字未満の中身の無い説明(「佐藤。」)は落とす**
7. 冒頭の段落選択も専用に行う。カッコ(読み)を除いた実質12文字未満の段落を捨て、姓の語を含む段落があればそこから後ろを使う(「五十嵐（いがらし／…）」の行を飛ばして「日本人における姓のひとつ。…」から採る)
8. **リダイレクト先が姓と無関係な記事なら捨てる**。「塙氏」は人物記事「祥光院」へ、「下村氏」「矢島氏」「滝沢氏」は「由利十二頭」へ、「山野辺氏」は「最上氏」へリダイレクトしており、そのまま採ると別の家の説明が入る。実際に開いた記事名が表記で始まらないリダイレクトは不採用にする(「近衛氏」→「近衛家」のような同じ家への改名リダイレクトは残る)。このために `wpnames.fetch_extracts` ではなくリダイレクト先も返す専用の取得関数を持つ
9. **説明文が姓・氏族の話になっていなければ捨てる**。記事名が姓のものでも中身が別物のことがある(「東 (姓)」→「東という一族。…麻雀において親（起家）にあたる位置。」、「新家」→「公家の格式の一つ。…」)。**説明文のどこか**に 姓 / 名字 / 苗字 / 氏族 / 一族 / 氏は / 家は / 武家 / 華族 / 氏の / 氏を / 氏流 / 豪族 / 名族 / 国人 のいずれかが含まれることを条件にする。記事名ではなく本文で判定するのは、曖昧さ回避ページが途中から別の話に移るため。あわせて 麻雀・「〜の格式」を含む説明は落とす
   - **判定は最初の一文ではなく説明文全体で行う**。氏族の記事には由緒から書き出して氏族の語が2文目以降に来るものが多く(金子「武蔵国多摩郡村山を領した平頼任が…金子を名乗ったのが始まりである。**現在でも埼玉県入間市から東京都清瀬市周辺にかけて金子の姓が多く見られる。**」)、先頭一文だけで判定すると、まさに欲しい分布情報を持つ行を落としてしまう
   - 判定語は「氏を」(小山「太田氏を出自とする地方豪族」)「氏流」(大橋「桓武平氏流貞能が…」)「豪族」「名族」「国人」までゆるめる。ゆるめたぶんの穴は下の人物記事ガードで塞ぐ
10. **主語に空白があれば人物記事なので捨てる**。ja.wikipedia の人物記事名は「姓 名」なので説明文の主語に空白が入る(「江口 光清は、安土桃山時代の…武将。最上氏の家臣。」)。姓・氏族の記事の主語(「佐藤氏」「日本の氏族」)には入らない。上の条件をゆるめると「◯◯氏の家臣」で人物記事が通ってしまうため、対で入れている
11. **主語が地物・企業の説明も捨てる**。「吹田城は、大阪府吹田市の…」「城田電気炉株式会社- …」のように、姓の記事が無くて城・駅・会社の記事に着地することがある。説明文の主語が 城 / 駅 / 市 / 町 / 村 / 川 / 山 / 藩 / 大学 / 神社 などで終わる場合と、株式会社・有限会社を含む場合は不採用にする

引く対象は **rank が付いた表記だけ**にする。順位の無い9万件近い表記には ja.wikipedia の姓記事がほぼ無く、問い合わせ回数に見合わないため。

### verified 列で「破格の読み」を落とさずに絞れるようにする

> **2026-08-13追記:** verifiedの裏付け範囲と出典記録は
> [ADR 00050](00050-myoji-evidence-sources.md)で拡張した。以下は初期設計時の判断を
> 記録したもので、現在はリポジトリ内の実在人名リストに加えてWeb NDL Authoritiesの
> 個人名典拠も `verified=yes` の根拠にする。JMnedictは辞書上の根拠として
> `evidence_sources` に記録するが、単独では `verified=yes` にしない。

SudachiDict の姓エントリには、実在の読みに混じって明らかに機械的・破格の読みが入っている。実測で見つかったもの: `伊藤 イロウ` / `井上 イトウ` / `星野 コシノ` / `慶滋 ヨシシゲノ` / `細渕 サイフチ` / `山敷 サンシキ` / `大庵 ダイアン` / `前濱門 マエハマジョウ` / `玉那覇 タマナワ`(正しくはタマナハ) / `庄喜 ツカギ`。空耳では `pronunciation` が変換のキーなので、これが混ざると変換結果が壊れる。

一方で `鈴木 ススキ` のように実在するが極めて稀な読みもあり、機械的に消すと本物まで落ちる。**このリポジトリの方針は「除外で削らずフラグで絞る」**なので、**行は消さず `verified` 列(yes/no)を足す**。

- 判定には**このリポジトリの実在人名リスト**を使う。`baseball.csv` / `football.csv` / `scientist.csv` / `youtuber.csv` の `type=family` 行から (surface, pronunciation) を集め、同じ組が1件でもあれば `yes`。**架空リスト(`fictional_*.csv`)は実在の裏付けにならないので使わない**
- 人名リストの読みはカタカナが基本だが scientist に一部ひらがなの行があるので、カタカナに揃えてから突き合わせる
- 初回生成での母集合は **8,994組**(baseball 9,374行 / football 6,208行 / scientist 3,176行 / youtuber 524行 の `type=family` から重複を除いたもの)
- **`no` は「誤り」を意味しない**。「実在人名リストで裏が取れなかった」だけで、(a) 実在するが稀な読み、(b) 名簿に載るほど有名な人がいない珍しい名字、も `no` になる。列の説明・README にこれを明記する。読みの確かさを求める利用側が `verified=yes` で絞れることが目的で、`no` の行を消すことは目的ではない
- 同じ id の中では **`verified=yes` の行を先に並べる**(`鈴木` なら スズキ が ススキ より先)。利用側が「最初の行を代表の読みとして採る」実装でも自然な読みが選ばれる
- 差分更新では **`no` → `yes` の一方向のみ更新する**。人名リストの行が減った回に `yes` を `no` へ落とすと、いったん取れた裏付けが消えるため(insect の `extinct` と同じ扱い。ADR 00014)
- **代替案として「破格の読みを機械判定して行ごと落とす」は採らなかった**。日本の姓の読みは規則性が乏しく(`四月一日`=ワタヌキ、`小鳥遊`=タカナシ)、機械判定は本物を落とす。フラグなら利用側が用途ごとに選べる

### wikidata 列は「人物の姓として最も多く使われている姓アイテム」

`wikidata` は rank の集計に使った姓アイテムの QID を入れる。同じラベルに複数の姓アイテムがあるときは、**実際に人物の P734 として最も多く使われている項目**(同数なら QID 番号の小さい方)を決定的に選ぶ。記事側の QID(曖昧さ回避ページ)ではなく姓の概念項目を入れるので、姓の同定キーとして使える。rank と同じ集計から出るので、**rank が空の行は wikidata も空**になる。

### 「多い都道府県」列は持たない

当初の要望には「どこに多いか」があった。世帯数と同じく、都道府県別の分布も再配布可能な出典が無いため**列としては持たない**(由来・分布の記述は ja.wikipedia の姓記事に書かれている範囲でのみ `description` に入る)。

候補として **[日本苗字アトラス](https://www.myoji-atlas.com/)**(都道府県別の順位・世帯数を公開)を調査したが、**再配布可とは判断できなかった**。同サイトの権利関係の記載は `about.html` の1ページだけで(利用規約・免責事項の独立ページは存在しない)、原文は次のとおり。

> 本サイトに所載のコンテンツ、テキスト等の著作権は、特に記載のない限り運営者に帰属します。本サイトの内容を転載・引用する場合は、出典URLを明記してください。
> (出典: https://www.myoji-atlas.com/about.html)

理由は2つ。

1. **許諾されているのは「転載・引用」であって、データセットの再配布ではない**。商用利用・スクレイピング/自動取得・二次利用については**一言も書かれていない**。CC 等の明示ライセンスも付いていない。「出典URLを明記すれば転載可」は、記事中で内容を引用する場面の話と読むのが自然で、構造化データを丸ごと別リポジトリで配布することまで含むとは読めない
2. **運営者が元データの権利を持っていない**。同ページの「出典」節に次の記載がある。

   > 電子電話帳データ（2007年時点）に基づき作成しました。
   > (出典: https://www.myoji-atlas.com/about.html)

   補正に使った資料として NTT ハローページ 個人版・住宅地図(ゼンリン、刊広社ほか)・実在苗字(名字)辞典等も挙げられている。著作権の記載自体が「**特に記載のない限り**運営者に帰属」と留保付きで、出典節がまさにその「特に記載のある」部分にあたる。運営者が持っていない権利を再配布許諾として与えることはできない。

したがって判定は**グレー(不可寄り)**で、ADR 00001 の基準3(再配布・クレジット表記が満たせること)を満たさない。将来入れるなら、運営者から個別に許諾を得るか、公的統計など出所が明確に自由利用可能な資料に当たること。

1つの漢字表記に複数の読みがある場合(`東` → アズマ / アヅマ / トウ / ヒガシ、`新谷` → シンタニ / シンヤ / ニイヤ)は、**同じ id のまま行を分ける**。空耳では読みが違えば別の材料になるので、まとめずに全部持つ。`original` と `surface` は同じ漢字表記で、行を分ける軸は `pronunciation` だけ。

### 差分方針(ADR 00014)

- 既存行の `id` / `original` / `pronunciation` は書き換えない。新しい(表記, 読み)の組だけ id 連番で追記する
- `description` / `wikidata` は**空欄の補完のみ**。上流の記事改稿でいったん埋めた説明が毎回書き換わるのを防ぐ
- `rank` だけは全行上書き(上記の理由)
- 妥当性ガード: SudachiDict から採れた組が 50,000 未満、または Wikidata の姓ラベルが 3,000 種未満なら実行を中断する

## Consequences

- myoji が pokemon / nations / stations / baseball / football / scientist / sekitsui / plant / insect / youtuber に続く自動更新対象になる
- **世帯数・実際の人口順位はこのリストからは分からない**。利用側が「日本で何番目に多い名字か」を知りたい場合は別途一次情報に当たる必要がある。`rank` を人口順位として表示する UI は作ってはいけない
- 初回生成(2026-08-02、SudachiDict 20260723)は **107,063行 / 漢字表記 91,836種**。うち複数の読みを持つ表記が 14,188種ある
- rank の付与率は低い(**表記 7,623種 = 8.3% / 10,202行 = 9.5%**)。SudachiDict は極めて珍しい名字まで収録している一方、Wikidata に人物項目がある名字は限られるため。**これは想定どおり**で、rank で昇順に並べれば実用的な上位が取れ、rank が空の行は「珍しい名字」の材料として使える。`wikidata` は rank と同じ集計から出るので付与率も同じ
- `verified=yes` は **4,316行 = 4.0%(表記 4,147種)**。rank が付いた行に限れば **2,989/10,202 = 29.3%**。空耳の材料として実用になる上位層は、rank と verified の組み合わせで十分絞れる
- description の付与率はさらに低い(**表記 1,060種 = 1.2% / 1,539行 = 1.4%**)。ja.wikipedia に姓の説明がある名字はもともと限られており、曖昧さ回避ページしか無い名字を無理に採ると人物一覧や地名の説明が入ってしまうので、採らないほうを選んでいる。由来・分布の語を含む説明は 119件(11.2%)
- **姓・氏族の語を説明文全体で見る + 人物記事ガード**という組み合わせに落ち着くまでに、「最初の一文だけで判定する」案を一度採って戻している。先頭一文だけだと金子・小山・立川・大崎・井口・木原・大橋・石橋のような**正しい氏族の説明を125種ぶん道連れにする**一方、全体で見ると「◯◯氏の家臣」を含む人物記事(江口 光清)が通ってしまう。前者は判定語をゆるめて拾い、後者は主語の空白で弾く、と役割を分けたほうが取りこぼしも誤採用も小さい
- なお `wikidata` 列は**姓アイテム**の QID(P734 の値)であって記事の QID ではないので、`instance of` で「その記事が氏族の記事か」を判定する用途には使えない。記事側の QID が要る場合は追加の取得が必要になる
- 行数が10万行規模になり、このリポジトリで最大のCSVになる。利用側は `rank` の有無・大小で絞れる
- SudachiDict の配布URLは S3 のバージョン付きディレクトリなので、**バージョンが増えるたびに自動的に最新を取りに行く**。辞書の更新で名字が増えれば月次バッチで追記される
- 名字の「発祥地」「多い都道府県」の類は、ja.wikipedia の姓記事に書かれている範囲でしか入らない(「静岡市周辺に多い姓。藤原南家の流れ。駿河国安倍郡藁科（静岡市葵区）発祥。」のように取れる名字もある)。書かれていない名字に後から補うなら、出典が明確で再配布可能なもの(自治体史・論文など)を都度確認して手で足すことになる。日本苗字アトラスは上記のとおり再配布可と判断できないので使わない
- `verified` は本リポジトリ内の他リストに依存する派生列なので、baseball/football/scientist/youtuber が育つと自動的に `yes` が増える。逆に、それらのリストに載らない層(一般人にしかいない名字)は永久に `no` のままになる
- 実在の人物名リストではなく**名字そのもの**のリストなので、パブリシティ権の懸念は生じない(個人を特定しない一般名詞に近い扱い)。ただし description には歴史上の氏族・人物名が含まれる

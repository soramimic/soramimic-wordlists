# ADR 00053: 未確認の名字読みを一般Webで独立再調査する

- Status: accepted
- Date: 2026-08-14
- Supersedes: ADR 00052の否定結果
- Related: 00038 / 00050 / 00051 / 00052

## Context

ADR 00052の公式サイト限定調査は、全候補を検索したという行数は記録したものの、検索要求の
成功、検索経路、取得結果を監査できなかった。実在する `榎谷 / エノキヤ` を
`no_support_found` としたことからも、旧ログの否定結果を再利用できない。なお否定結果は
「実在しない」という証明ではなく、その時点で裏付けを発見できなかったという状態にすぎない。

## Decision

既に `verified=yes` の行は再調査せず、現在 `verified=no` の全行を新しい候補スナップショット
へ固定して独立に再検索する。旧公式Webログは検索済み除外に使わない。

未確認の結果を受理するには、各候補で次を満たす検索receiptを必須とする。

- 漢字表記＋カタカナ読み、漢字表記＋ひらがな読み、人物を示す語を加えた検索の3戦略
- 3戦略それぞれについて実際に完了した検索サービス（統合検索はそのサービス名で記録する）
- 検索日時、検索語、応答状態、候補に対応する到達先URL、receiptのSHA-256
- 429等の失敗応答は保持できるが、成功経路には数えない
- 実行していない個別検索エンジン名を統合検索のreceiptへ代入しない
- 検索ページ、中継URL、壊れたURL、別候補の結果URLを到達先として記録しない
- 不一致の検索結果も上位到達先URLとして残す。まとまったバッチでURL返却がほぼゼロなら、
  完了した否定調査ではなく検索サービスの空応答としてバッチ全体を拒否する
- 検索結果スニペットは監査receiptの同一性に含めず、配布時に除去する。検索語、日時、
  応答状態、到達先URL、応答本文のハッシュだけを保存し、第三者ページ本文を再配布しない

正例は、姓表記と読みが同じ人物の同じ行・記録・プロフィールにある場合だけ採用する。
官公庁・学校・大学・競技団体・企業開示・専門職名簿等をTier A、報道・出版社・信頼できる
人物データベース等をTier Bとし、いずれも原ページのHTTPS URLと確認箇所を保存する。
姓辞典、検索スニペット、SNS投稿だけでは `verified=yes` にしない。

配布物へページ本文や名簿を複製せず、事実判定、短い確認箇所、根拠URLだけを
`tools/myoji_web_evidence.jsonl` に置く。採用行の `evidence_sources` は `web_person` とする。
採用台帳にはschema-v3 URL本文監査票を対応させ、全行について同じURLで姓表記と読みが
近接した `pass` を必須とする。台帳の確認箇所は監査票の本文文脈と一致させる。

## Consequences

検索失敗やレート制限を否定結果として隠せず、候補の取り違えもレビューしやすくなる。一方で、
7万件超を複数経路で調べるため処理時間は大きくなる。小さなバッチを検証し、無作為抽出と
既知の正例を品質対照にしてから処理単位を広げる。

ADR 00052で得た正例の根拠は引き続き利用できるが、同ADRの `no_support_found` と
「全件検索済み」という結論は、この再調査の完了判定には用いない。

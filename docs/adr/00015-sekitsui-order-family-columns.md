# ADR 00015: sekitsui.csv の目・科(order/family)列

- Status: accepted
- Date: 2026-07-27
- Supersedes: none
- Superseded by: none

## Context

sekitsui.csv の分類情報は `class` 列の大分類(哺乳類/鳥類/爬虫類/両生類/魚類)だけで、粒度が粗い。「ネコ科の動物」「カモ目の鳥」のように、もう少し細かい単位で絞り込んで空耳変換の候補を作りたい。

Wikidata の taxon には親タクソン(P171)と階級(P105)があり、種から親を辿れば目(Q36602)・科(Q35409)に到達できる。ただし WDQS に `wdt:P171*` の推移閉包を 14000 件の VALUES で解かせると必ずタイムアウトする(単発の QID でも 60 秒で返らない)。一方、親を 1 段だけ引くクエリは 500 件バッチで約 3 秒と十分速い。

階級のラベルは Wikidata の日本語ラベルがそのまま使えるとは限らない。Anura(カエル目)はラベルが「カエル」で、階級を表す「目」が付かない。目・科で絞り込む列としては語尾が揃っていないと使いにくい。

また `wikidata` 列は `enrich_sekitsui_images.py` が画像とセットで埋める列なので、画像の無い行(約2700行)は QID が空のままになっている。

## Decision

- `sekitsui.csv` に `order`(目)・`family`(科)列を `extinct` の後ろに追加する。値は日本語の階級名(例 `ネコ目` / `ネコ科`)。`class` や `lines` と同じく言語サフィックスは付けない(学名にフォールバックすることがあるため `_ja` はむしろ不正確になる)
- 取得は `tools/enrich_sekitsui_taxonomy.py`。推移閉包は使わず、親(P171)を 1 段ずつ幅優先で辿る。目に達した枝はそこで打ち切る(科は目より下なので取り逃さない)
- 取得したノード(親・階級・ラベル・学名)は `tools/.cache/` に逐次保存し、中断しても再実行で続きから再開できるようにする(Git 管理外)
- 表示名の優先順は「階級付きの日本語別名(skos:altLabel、語尾が目/科のもの) > 日本語ラベル > 学名(P225)」。Anura は別名の「カエル目」を採る
- `wikidata` 列が空の行は和名(original)から Wikidata のタクソンを逆引きして補う。同名候補が複数あるときは rank=種 を優先する。逆引きした QID は CSV には書かない(`wikidata` 列は画像とセットで埋める列のままにする)
- 既定では order/family が空の行だけ埋める(冪等)。`--refresh` で全行引き直し
- どちらも取れない行は空のままにする(`image` 列等と同じ扱い)。利用側は空でも動くこと
- 月次バッチ(update-wordlists.yml)には入れず手動実行とする。`enrich_sekitsui_images.py` と同じ扱い

## Consequences

- 目・科での絞り込みができるようになる。QID を持つ行はほぼ全件、CSV 全体でも大半の行に値が入る
- 値はスナップショットであり、分類体系の改訂には自動追従しない。気になったら `--refresh` を手動実行する
- 目・科が Wikidata 上で未整備・不明な行(化石種や古い和名に多い)は空のままになる
- 列が増えたので、書き出し列をハードコードしているスクリプトは列落ちを起こす。`enrich_sekitsui_images.py` を実ファイルのヘッダー追随に直した(ADR 00014 と同じ方針)

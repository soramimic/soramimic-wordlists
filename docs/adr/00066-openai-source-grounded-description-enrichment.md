# ADR 00066: OpenAI APIは出典完全一致の説明文選択だけに使う

- Status: accepted
- Date: 2026-08-26
- Supersedes: none
- Superseded by: none
- Related: [00014](00014-no-degrading-existing-rows.md)（既存値の保護） / [00043](00043-player-descriptions.md)（選手の説明文） / [00045](00045-youtuber-description-curation.md)（YouTuberの説明文）

## Context

説明文の未完文、前後の文脈に依存する表現、カード上の名前と重複する主語、内容の
乏しい一般的な肩書きは、決定的な検証で候補を検出できても、どの文を採用すべきかを
規則だけで決めにくい。一方、LLMに自由な要約や補完をさせると、出典にない情報の
追加や別人との取り違えを検証しにくくなる。

OpenAI APIのdata-sharing incentiveは、利用資格、対象モデル、トークン量、更新周期が
固定された無償契約ではない。data sharingを有効にしたことやAPI残高を入れたことだけ
では利用資格を保証せず、表示や条件は後から変わりうる。また、外部APIの計測遅延、
並行したtraffic、再試行などがあるため、ローカルの上限だけで請求を完全には防げない。

## Decision

### 対象とする補助

LLMを使えるのは、次の条件をすべて満たす `description` の候補選択だけとする。

- 行の同定が既存の決定的な処理で完了しており、対象行と出典本文の対応が確定している
- 許可された公開出典の本文、出典URL、取得時点または版が入力前に固定されている
- LLMは、入力された出典本文に文字列として完全一致する連続した抜粋を一つ選ぶか、
  採用可能な抜粋がないと回答する。言い換え、要約、接続、補完、新事実の追加はしない
- 選択結果は、出典本文との完全一致、完結した文、長さ、禁止表現、主語の重複など、
  リスト固有の決定的な検証をすべて通過した場合だけ変更候補にする
- 一致しない出力、検証できない出力、複数候補の判断根拠が不足する場合は棄却し、
  既存値を保持する。LLMの出力だけを根拠にCSVへ新しい事実を書かない

LLMを使わず決定的に直せる空白、句読点、既知の固定置換、列形式、重複行は従来の
処理で直す。LLMは検出規則の代替ではなく、出典中の複数の適格候補から内容のある
説明文を選ぶ部分だけを担当する。

### 対象外

次はLLMによる補正対象にしない。

- 人物・生物・作品などの同定、収録可否、`id`、`original`、表記の対応付け
- 読み、発音、表層形、別名の判定
- `category`、`type`、`subject`、`field`、`class`、`order`、`family`、`scope` などの
  分類・所属・対象範囲の判定
- 出典がない行、同名対象を一意に確定できない行、複数出典の統合やモデルの既知知識を
  必要とする補完
- 時変値、数値、画像、ライセンス、センシティブ判定など `description` 以外の値

これらは決定的な一次資料、既存の根拠台帳、または個別レビューで扱う。根拠が不足する
値は無理に埋めず、既存値または `NA` を維持する。

### 実行前提と使用量上限

data-sharing incentiveを前提に実行するときは、次の条件を必須とする。

1. この処理専用のOpenAI API projectと、そのproject専用のAPI keyを使う。別の処理や
   利用者とproject・keyを共用しない。
2. 実行直前にOpenAI PlatformのData controlsで、対象projectのdata sharingが有効で、
   対象モデルのcomplimentary daily tokensへの登録と現在の枠が表示されていることを
   人が確認する。data sharingを有効にしただけで資格ありとはみなさない。
3. 確認の有効期限を `OPENAI_DATA_SHARING_INCENTIVE_CONFIRMED_UNTIL=YYYY-MM-DD`
   として設定する。この値は、専用API keyのproject、対象モデル、表示枠、正の残高を
   Data controlsで確認済みであるという運用者の表明とする。欠落・期限切れ時はAPIを
   呼ばず、Data controlsを再確認する。
4. incentive dayごとの使用量台帳を持つ。表示枠が250万token以上の場合でも、
   入力・出力と再試行を合計した内部上限を200万tokenとし、50万token以上の余裕を
   残す。各requestの送信前に最大使用量を予約し、上限を超えうるrequestは送らない。
   表示枠がこれより小さい、または確認できない場合は、この上限を安全根拠にしない。
   runner消失時には最新台帳を回収できない可能性があるため、API送信前にrepository
   全体から照合できるimmutable artifactとして当日claimと翌日guardを保存する。artifact
   の保存とAPI照合、UTC日の再確認がすべて成功した場合だけ送信する。結果にかかわらず
   翌日guardを残し、同じUTC日とその翌日の再実行を拒否する。SQLite台帳とresponse
   cacheは同一run内の上限管理とbest-effortな再利用に使い、branch間やjob消失後の保存を
   安全根拠にしない。2日後の再送は新しいincentive dayの枠として扱う。
5. requestは `service_tier="default"`、`store=false` とし、toolsを渡さない。tool use、
   priority・flex・fast相当の別tier、background処理はこの運用に含めない。
6. 専用projectには許容できる最小のhard spend limitを別途設定し、enforcementが有効な
   ことを確認する。広い権限を持つAdmin keyは月次workflowへ保存しない。

これらは誤課金の可能性を小さくする停止条件であり、絶対に無課金であることの保証では
ない。OpenAI側の条件変更・計測遅延、台帳外のtraffic、同時実行、通信失敗後の再試行
でも費用が発生しうる。費用発生を一切許容できない環境では外部APIを実行しない。

入力と出力がdata sharingの対象になるため、送信するのは公開済みで、この用途で扱える
出典本文と必要最小限の行情報に限る。非公開データ、認証情報、不要な個人情報は送らない。

採用した説明は、対象リストとID、Wikipedia記事・QID・版ID、選択した元文、最終説明、
モデルとprompt versionを公開根拠台帳へ一対一で固定する。本人同定不能、abstain、
決定的検証で棄却した当月候補は未解決台帳へ残し、次回以降も公平に再確認する。

### 既存データの扱い

このADRと初期実装は運用境界と新しい候補選択を定めるもので、既存CSVの `NA`、
`NA。`、空欄、既存説明文を一括で書き換えない。既存行のbulk migrationは、対象リスト、
出典対応、サンプル監査、検証ゲート、変更件数を明示した別PRで行う。

## Consequences

- 規則だけでは選びにくい説明文でも、出典にない文章を生成せず候補を比較できる
- 同定・読み・分類の判断をLLMから分離し、誤りを決定的な検証で停止できる
- 適格な完全一致抜粋がない行では改善を見送り、`NA` や既存の説明が残る
- 適格表示と使用量を実行ごとに確認する運用負担が増え、条件変更時には実行を停止する
- 200万tokenの内部上限は余裕を設けるが、外部APIの費用を完全には保証できない
- OpenAI補完の成否にかかわらず同じUTC日とその翌日には再実行せず、claimがない
  UTC日（最短で2日後）まで待つ

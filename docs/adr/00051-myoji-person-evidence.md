# ADR 00051: 名字の実在人名裏付けをWikidataと公式人物ページへ広げる

- Status: accepted
- Date: 2026-08-13
- Supersedes: 00050のverified判定ソース
- Superseded by: none
- Related: 00001 / 00014 / 00038 / 00050

## Context

ADR 00050でWeb NDL Authoritiesを加え、実在人名で確認済みの読みは35,490組まで
増えた。しかしNDLに典拠がない人物や分野は拾えず、`verified=no`が多数残る。
ウェブ上には大学・官公庁等の公式人物ページもあるが、サイトごとの本文を集積・再配布
する必要はない。目的は公開情報から「この姓表記と読みを持つ実在人物がいる」という
事実を確認することである。

Wikidataには、日本国籍の人物の姓(`P734`)が姓アイテムを参照し、その姓アイテム自身に
かな表記(`P1814`)がある組が約6千件ある。これはCC0の構造化データで、自動更新に向く。

## Decision

`evidence_sources` に次の2トークンを追加し、どちらも実在人名の裏付けとして
`verified=yes` にする。

- `wikidata_person`: `P31=Q5`、`P27=Q17`の人物が`P734`で使う姓アイテム自身の
  日本語ラベルと`P1814`の一致
- `official_web`: 公式人物ページのレビュー済み確認台帳との一致

Wikidataでは人物のフルネームに付いた`P1814`を機械分割しない。姓名順・空白・複合姓で
誤るため、姓アイテム自身の読みだけを採る。参照付きstatementには限定しない。
Wikidataの参照付与は不完全で、ここではWikidata構造化データとの一致を表すためである。
取得が一時的に欠けた応答をキャッシュしないよう、4,000組未満なら失敗させる。

公式ページは `tools/myoji_official_evidence.jsonl` に1確認1行で記録する。候補の表記・読み、
確認状態、HTTPS URL、公式ソース種別、ページ表題、確認日、ページ上の表記・読み、確認箇所を
必須にする。`status=verified`で、ページ上の姓と読みが候補に正規化一致する行だけを採用する。
本文・名簿はコピーせず、判定と監査に必要な最小限のメタデータだけを再配布する。

公式ページ探索は個別確認に限り、各サイトの利用条件、robots、アクセス制限を守る。
ログイン回避や大量クロールは行わない。姓読みという事実の確認が目的でも、アクセス方法に
関する条件が不要になるわけではない。

## Consequences

- NDL外の人物も、追跡可能な根拠で確認済みにできる
- 自動取得のWikidataと人手確認の公式ページをトークンで区別できる
- 公式ページの移転・削除後も確認時点とURLは残るが、定期的なリンク監査は別途必要
- 公式ページに別の読みの人物がいても、候補読みが存在しない証明にはならないため、
  誤読候補の自動削除には使わない

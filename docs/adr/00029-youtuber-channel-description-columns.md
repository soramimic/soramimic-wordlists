# ADR 00029: youtuber.csv に channel(メインチャンネル名)と description(短い説明文)を追加する

- Status: accepted
- Date: 2026-07-30
- Supersedes: none
- Superseded by: none
- Related: 00011(youtuber/vtuber リストの収録基準) / 00014(既存行を劣化させない・空欄補完のみ) / 00023(debut_year をチャンネル開設年で補う)

## Context

youtuber.csv が持っている情報は活動名・読み・category・org・debut_year・status・
画像だけで、**その人が何をしている人かが分からない**。同名・似た名前の人の区別も
できず、利用側(ソラミミック)で動画キャプションに出せる説明文もない。
scientist.csv には同じ目的の `description`(記事冒頭からの短い完結文)が既にあり、
youtuber にも同じものが欲しい。

もう1つ欠けているのが**チャンネル名**である。このリストの original は ja.wikipedia の
記事名(活動名)なので、「HIKAKIN」のように活動名とチャンネル名が違う人や、
「Nene Ch.桃鈴ねね」のようにチャンネル名だけが英字表記の人を、チャンネル名側から
引くことができない。

Wikidata 側の実測(対象1101人、2026-07時点):

| 取得元 | 該当人数 |
|---|---|
| P2397(YouTubeチャンネルID) | 804人 |
| P2397 の修飾子 P1810(チャンネル名 = subject named as) | 775人 |
| ja description(schema:description) | 906人 |

記事冒頭文(`fetch_extracts`)は既に全員分取得しているので、description の追加で
増える通信は無い。channel も既存の `fetch_attrs` の SPARQL に `OPTIONAL` を
足すだけで済む。

## Decision

1. **`channel` 列 = メインYouTubeチャンネル名**。P2397 の修飾子 P1810 から取り、
   取り消し済み(DeprecatedRank)の文は除く(既存の P580 取得と同じ扱い)。
   **複数チャンネルを持つ人は登録者数(修飾子 P3744)が最大の1本をメインとみなす**。
   サブチャンネル・切り抜き・YouTube が自動生成する「- Topic」チャンネルまで
   P2397 に並ぶため、単純に最初の1本を採ると `Ironmouse - Topic` のような
   本人が使っていない名前が入る。登録者数が無いチャンネルしか無い場合は
   名前の昇順で先頭を採る(実行ごとに値が揺れないため)。org と同様に ASCII
   カンマ・二重引用符は除去し、無ければ `NA`
   - チャンネル名と登録者数は同じ P2397 文の修飾子なので、`GROUP_CONCAT` で
     別々に集約すると対応が失われる。`"登録者数@@チャンネル名"` に連結して
     1変数で集約し、どれがメインかは Python 側(`_main_channel`)で決める
2. **`description` 列 = scientist と同じ生成方式**。記事冒頭文から先頭の生没年
   カッコと冒頭の「{人名}は、」を除去し、「。」区切りで完結文を目安90字まで連結。
   記事冒頭が無ければ Wikidata の ja description、どちらも無ければ `NA`。
   実装は `update_scientist.py` にあった `make_description` とその補助関数を
   **`tools/wpnames.py` へ移して共用する**(scientist の出力は変えない)
3. **description に本名を持ち込まない**(`yt_common.deidentify`)。このリストは
   活動名だけを収録する方針(ADR 00011)だが、**ja.wikipedia の記事冒頭には本名が
   よく書かれている**。実測では1068記事のうち80記事の冒頭から作った description に
   「本名は〜」等が入り、さらに「{本名}は、{活動名}として知られる〜」で始まる記事も
   多数あった。そこで記事冒頭を description に使う前に:
   - 「本名」「実名」「戸籍名」「出生名」「旧姓」を含む**文を丸ごと捨てる**
   - 文頭が活動名以外の人名の「{本名}は、〜」なら**その主語を落として述部だけ残す**。
     人名とみなすのは姓名の空白・中黒を含む語(「水戸 由菜は、」「アラン・オラフ・
     ウォーカーは、」)か、「〜として知られる」等が続く1語の名前(「アレクサンダーは、
     テクノブレードとして知られる〜」)。「コムドットは、〜」のようなグループ名・
     屋号は落とさない
   - Wikidata の ja description 側も同じキーワードを含むものはフォールバックに使わない
4. **列順は既存ファイルの末尾に足す**。`COLS`(新規ファイル用)にも加え、既存CSVを
   読むときは fieldnames に無い列を末尾に追加する。利用側は列名で読むので位置は問わない
5. **既存行は空欄補完のみ**(ADR 00014)。org/debut_year と同じループで扱う。
   新設列は全行が空なので実質全員が対象になるが、以後の実行では既に入っている値を
   書き換えない。照合できなかった行(EXCLUDED 等)は空ではなく `NA` にして列の意味を揃える

## Consequences

- 実行結果(2026-07-30、既存973人): `channel` は686人(71%)、`description` は964人
  (99%)が埋まった。description は記事冒頭が取れれば必ず作れるので、Wikidata の
  ja description が無い人もほぼ埋まる。既存列の値は1つも変わらず、差分は新列の
  書き込みと新規1人の追記だけ
- 利用側で「チャンネル名で探す」「キャプションに一言説明を出す」ができるようになる。
  検索キーとして使うなら surface に足すのではなく channel 列を見ること
  (channel は表示・照合用の情報列で、読み(pronunciation)は付かない)
- **トレードオフ: メインチャンネルの選び方は登録者数まかせ**。本人が主戦場と
  考えているチャンネルと一致しない場合がある(例: サブチャンネルの方が登録者数が
  多い人、ゲーム実況チャンネルが最大の人)。またWikidataの登録者数は更新時点の
  スナップショットなので、順位が入れ替われば次回以降 channel が変わりうる。
  ただし空欄補完のみなので、**一度入った値が自動で書き換わることはない**
- **トレードオフ: description は記事冒頭文の要約ではなく先頭の切り出し**なので、
  冒頭が定義文でない記事では説明として弱い文が入る(グループ記事へのリダイレクトの
  人は、その人ではなくグループの説明になる)。scientist と同じ既知の制約
- **本名フィルタは機械的な検出に限る**。キーワードも「〜として知られる」構文も
  無いまま文中に本名が出る記事(「『The Anime Man』は、ジョーイ・ビジンジャーによる
  〜」等)は残りうる。気付いたら EXCLUDED ではなく description 側の手修正で対応する
  (既存値は自動更新で書き換わらない)。同様に、本人が本名でチャンネルを名乗って
  いる場合は `channel` にその名前が入る(チャンネルの公称名なのでそのまま採る)
- description は Wikipedia 由来(CC BY-SA 4.0)。youtuber.csv は既に読み・org を
  Wikipedia/Wikidata から取っているので出典・帰属の扱いは変わらない
- 月次バッチの差分に既存2020行への新列書き込みが1回だけ大量に出る。以後は
  新規追加分と空欄補完だけになる

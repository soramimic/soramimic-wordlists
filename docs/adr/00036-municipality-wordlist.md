# ADR 00036: municipality(市区町村)ワードリストの新規作成と自動更新

- Status: accepted
- Date: 2026-08-02
- Supersedes: none
- Superseded by: none
- Related: 00001(自動更新の出典選定基準) / 00003(nations の正式名称・通称と status) / 00004(stations の差分更新と永続キー) / 00009(scientist の description 生成) / 00014(既存行を劣化させない)

## Context

地名は空耳の材料として使い出があるのに、既存リストには駅名(stations)しか入っていない。駅名は「〜駅」に偏っていて、しかも駅の無い自治体は表に出てこない。市区町村名は日本全国を隙間なく覆う語彙で、`札幌`『さっぽろ』のように接尾辞を落とした形が日常語としてそのまま通じるものが多い。

一方、市区町村は他リストと違って **1つの語に対して「正式名称」と「通称(接尾辞を落とした形)」が機械的に対応する**。`札幌市` と `札幌`、`千代田区` と `千代田` はどちらも実用の表層で、空耳の材料としては後者の方が使いやすい場面が多い。nations が「大韓民国 / 韓国 / 韓」を同じ id で併記しているのと同じ構造にできる(ADR 00003)。

出典の候補は3系統ある。

1. **総務省「全国地方公共団体コード」**: 現存する市区町村の唯一の一次情報。団体コード・都道府県・**カナ表記**まで揃っていて、読みを推定しなくてよい。Excel(xlsx)配布
2. **Wikidata**: 廃止・合併消滅した旧自治体が「廃止された日本の市町村」Q18663566 の配下に約15,000件ある。総務省の現行コード表には現存分しか載っていないので、廃止分はここでしか取れない
3. **e-Stat(国勢調査)**: 市区町村別人口。団体コードで突合できる

## Decision

`tools/update_municipality.py` を月次バッチに追加し、上の3系統から `municipality.csv` を生成する。ADR 00001 の4基準(機械可読 / 認証不要 / 再配布可能なライセンス / 差分追記)を満たす。

### 列構成

`id, original, surface, pronunciation, type, prefecture, parent, status, population, code, description, wikidata`

### 1自治体 = 1 id、表層は full / short の2行まで

- `type=full`: 正式名称そのまま(`札幌市`)。読みも出典のカナそのまま(`サッポロシ`)
- `type=short`: 末尾の 市/区/町/村 を1文字落とした形(`札幌`)。読みも接尾辞の読みを落とす(`サッポロ`)
- **落とすと空になる・落とした結果が full と同じになる・同じ id 内で表層が重複する場合は short 行を作らない**

接尾辞の読みは漢字と1対1ではない(町=チョウ/マチ、村=ソン/ムラ)。**推定せず、出典のカナの末尾に一致した方を落とす**(`日の出町`=ヒノデマチ → ヒノデ、`風連町`=フウレンチョウ → フウレン)。一致しなければ short の読みは空にする。初回生成では現存1,918件すべてで short が作れ、読みも全件付いた。

`四日市市`(ヨッカイチシ→ヨッカイチ)・`野々市市`(ノノイチシ→ノノイチ)・`町田市`(マチダシ→マチダ)のように接尾辞と同じ字が名前側にも出る自治体は多いが、**接尾辞は必ず末尾1文字**なので末尾だけを見る限り取り違えない。

### 現存は総務省のコード表が母集団

- 現行コード表(xlsx)の Sheet1(都道府県+市区町村)から市区町村名が入っている行、Sheet2(政令指定都市)から行政区の行を採る。初回生成(2026-08-02)は **1,747 + 171 = 1,918 件**(市792 / 町743 / 村189 / 区194 = 特別区23 + 政令指定都市20市の行政区171)
- 都道府県だけの行(市区町村名が空)は自治体ではないので落とす
- **北方領土の6村(色丹村・泊村・留夜別村・留別村・紗那村・蘂取村)はコード表にあるので `status=current` で収録する**(村が一般に言われる183ではなく189になるのはこのため)。法令上の位置づけをそのまま反映しており、このリポジトリが独自の判断を足さない方針に合う。国勢調査の人口は無いので Wikidata 側の値が入る

### 政令指定都市の行政区は `parent` で見分ける

コード表は行政区を `札幌市中央区` という連結表記で持っているが、**`original` は区名だけ(`中央区`)にして、親の市名を `parent` 列に置く**。

- 空耳の材料として使うのは `中央区`・`中央` であって `札幌市中央区` ではない。連結表記のままだと short が `札幌市中央` になって日本語として成立しない
- `中央区`・`北区`・`西区` のような同名の区は10前後あるが、**id が別なので表層の重複にはならない**(府中市/府中町が別 id なのと同じ)。利用側が区別したいときは `parent` を見る
- 特別区(千代田区など)は市町村と同格の基礎自治体なので `parent` は空にする
- 行政区のカナは連結表記のカナ(`ｻｯﾎﾟﾛｼﾁｭｳｵｳｸ`)から親市のカナ(`ｻｯﾎﾟﾛｼ`)を前方一致で落として求める。Sheet2 には親市の行も入っているので、この対応は同じシート内で閉じる

### 廃止自治体は Wikidata から広く収録する

「広く収録してフラグで絞る」方針に従い、廃止・合併消滅・改称前の旧名を `status=former` で入れる。除外ではなくフラグなので、現存だけ使いたい利用側は `status=current` で絞ればよい。

- 対象は Q18663566(廃止された日本の市町村)の `wdt:P31/wdt:P279*` 閉包。ラベル(ja)・読み仮名(P1814)・廃止日(P576)・団体コード(P429)・所属(P131)・人口(P1082)・ja.wikipedia のサイトリンクを一括で採る
- **ラベルの括弧注記は落とす**。Wikidata の日本語ラベルには `大島町 (東京都)` のような曖昧さ回避が入っているものがあるので、対応の取れた括弧を再帰的に除去する
- 除去後に **末尾が 市/区/町/村 でない行・漢字かなカタカナ以外の文字を含む行は落とす**(郡・支庁・非日本語ラベル・Q番号のまま残っている行など)
- **現存と (名称, 都道府県) が一致する行は落とす**。同じ表層が現存側にもある場合、廃止側の行を足しても空耳の材料は増えず、id だけが増える
- 同じ (名称, 都道府県, 廃止日) の行は1件に寄せる

初回生成では候補15,268件のうち **134件だけを落として15,134件を収録した**(ラベル不正5 / 末尾が市区町村でない24(郡・新田・団体名など) / 現存と同名21 / 重複84)。落ちる割合が1%未満なので、フィルタが本物の自治体を巻き込んでいる恐れは小さい。

`prefecture` は `wdt:P131*` を都道府県クラス(Q50337)まで遡って求めるが、**採用するのは現行47都道府県の名前だけ**にする。廃藩置県期の県(飾磨県・鶴岡県など)にも繋がるので、そのまま入れると `prefecture` 列が絞り込みに使えなくなる。到達しない行は空にする(15,134件中214件)。

**総務省の「改正一覧表」との突合は行わない**。都道府県が引けなかった214件の内訳は東京市とその配下の町村(1932年の東京市編入。所属が東京府にしか繋がらない)と樺太の市町村で、改正一覧表がカバーするのは2005年4月以降の改正なので**1件も埋まらない**。1.4%のために出典を1つ増やす価値が無い。

### 人口は国勢調査を優先し、Wikidata で補う

- 現存: **e-Stat の令和2年(2020年)国勢調査「都道府県・市区町村別の主な結果」**(統計表個別ファイルの直リンク、APIキー不要)。5桁の標準地域コードで突合する(団体コードの先頭5桁 = 検査数字を除いた部分)。行政区も含めて1,916件ぶん入っている
- **確定した過去の公表なので `statInfId` が変わらない**。住民基本台帳人口の方が新しいが、公表のたびにExcelのファイルIDが変わって直リンクを固定できないので採らない
- 取れない行(北方領土の6村・2020年以降にできた浜松市の3区・全町避難していた双葉町など10件)と廃止自治体は、**Wikidata の P1082 のうち時点(P585)が最新のもの**で補う。取れなければ空
- どちらの出典から入った値かは列としては持たない。`status=current` なら原則2020年国勢調査、`former` なら Wikidata と読める

### description は scientist と同じ生成方式

ja.wikipedia の記事冒頭(`action=query&prop=extracts&exintro`)から、先頭の読みカッコと冒頭の「{自治体名}は、」を落として「。」区切りの完結文を目安90字まで連結する(`wpnames.make_description`)。ASCIIカンマ・二重引用符は除去する。記事が無ければ空。

「福岡県糸島郡にあった町。」「静岡県の東部にあった市。」のように、**その自治体がどこの何だったかが1文で分かる**ので、廃止自治体の手がかりとして効く。

### 画像は持たない

市区町村の「写真」は庁舎・風景・市章のいずれを採っても代表性が無く、市章・旗は自治体の著作物・商標にあたりうる。scientist の象徴カードのような生成画像を作る利点も薄いので、**`image` / `image_page` 列自体を持たない**。

### 生成方式は「全件再生成 + id の引き継ぎ」

- 毎回すべての行を作り直すが、**id は既存CSVのキーから引き継ぐ**。キーは現存が団体コード、廃止が QID。**改称した自治体は旧名と新名で団体コードが同じ**(篠山市 → 丹波篠山市)なので、現存と廃止でキーの名前空間を分けないと衝突する
- 列の値は **今回取得できたときだけ上書きする**(ADR 00014)。出典側の一時的な欠落で既存の読み・人口・説明文を空に落とさない
- 総務省のコード表から消えた現存行(合併等)は **行を消さずに `status=former` に落とす**。stations が廃止駅を former にして残すのと同じ
- 妥当性ガード: 現存が1,700件、廃止が8,000件を下回ったら取得失敗とみなして中断する

初回生成の結果は **34,104行 / 17,052自治体(現存1,918 / 廃止15,134)**。列の充足率は次のとおり(かっこ内は `status=current` の行だけの充足率)。

| 列 | 充足率 |
|---|---|
| pronunciation | 91.5% (現存 100%) |
| prefecture | 98.8% (現存 100%) |
| population | 11.6% (現存 100%) |
| code | 11.3% (現存 100%) |
| description | 98.4% (現存 99.7%) |
| wikidata | 100% (現存 100%) |

`population` / `code` が全体で1割強にとどまるのは、廃止自治体の大半が住民基本台帳も団体コードも整備される前(明治〜昭和初期)に消えているためで、取りこぼしではない。

### openpyxl は使わず標準ライブラリで xlsx を読む

`tools/` の updater は依存パッケージ無し(`pyproject.toml` の `dependencies = []`)で GitHub Actions の素の Python から動く前提なので、**xlsx(zip + OOXML)を `zipfile` + `xml.etree` で読む最小実装をスクリプト内に持つ**。

このとき **ふりがな(`rPh`)を本文として拾わない**ことに注意する。総務省のコード表は一部のセルにふりがなが埋まっていて、`si` 配下の `t` を素朴に全部連結すると `熊本市西区クマモトシニシク` のように漢字とカナが繋がった値になる。

### 取得結果は tools/.cache/ に貯める

Wikidata の廃止自治体(約15,000件)と ja.wikipedia の記事冒頭(約17,000件)は取得に数十分かかるので、`tools/.cache/municipality/`(Git管理外)に逐次保存し、再実行では取得済みのタイトルを引き直さない。全件引き直しは `--refresh`。

## Consequences

- municipality が pokemon / nations / stations / baseball / football / scientist / sekitsui / plant / insect / youtuber に続く自動更新対象になる
- **同じ表層が複数の id に現れる**。`中央区` は政令指定都市の数だけあり、`大和町`・`大和村` のような廃止自治体名は全国に散らばっている。表層の重複は id が別なので仕様どおりだが、利用側が「1つの語 = 1つの自治体」と思い込むと誤解する。区別が要るときは `prefecture` / `parent` / `status` を見ること
- **`short` の表層は地名以外の一般語と衝突する**。1文字になる表層が605行あり(`旭`33件・`東`31件・`中`26件・`泉`19件…)、`中央`・`緑`・`北` のような語がそのまま入る。一般語を避けたい利用側は `type=full` で絞る必要がある
- **「改称前の旧名」は Wikidata 側の作りに依存する**。篠山市→丹波篠山市のように改称した自治体は、Wikidata では1つの項目が現在の名前のラベルを持つだけで廃止クラスには入らないので、旧名の行はできない。旧名も欲しくなったら nations と同じく手で行を足す(`status=former`・`parent` 空・同じ id ではなく別 id で入れる)
- 廃止自治体を広く入れたぶん、現存(約1,900)より廃止(1万超)の方がずっと多いリストになる。既定で現存だけを使いたい利用側は `status=current` を必ず指定すること
- e-Stat の国勢調査は5年ごとなので、次の公表(令和7年=2025年国勢調査)が出たら `ESTAT_CENSUS_XLSX` と `CENSUS_YEAR` を差し替える。差し替えるまで人口は2020年の値のまま固定される(時変値を毎回上書きする youtuber の `subscribers`(ADR 00030)とは違い、**基準時点が明示できる統計値なので固定でよい**)
- 総務省のコード表は改定のたびに `main_content/` 配下のファイル名(数字)が変わる。URLを直書きしているので、404になったら https://www.soumu.go.jp/denshijiti/code.html から新しいURLを拾って差し替える必要がある。取得に失敗した回は妥当性ガードで中断し、月次バッチは `continue-on-error` で他のリストだけ更新される
- 廃止自治体は Wikidata 側の整備状況に依存する。読み仮名(P1814)が無い行は `pronunciation` が空になり、利用側は表層から読みを推定することになる
- 市区町村より下の地名(大字・町丁目)、郡、支庁・振興局は収録しない。必要になったら別リストにする

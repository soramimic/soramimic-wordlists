# ADR 00014: 自動更新は既存行の埋まっている値を劣化させない

- Status: accepted
- Date: 2026-07-26
- Supersedes: 00007 / 00008 の「既存行にも Wikidata から分類・絶滅フラグを付与し、引けなかった行は NA(絶滅は no)とする」判断、および 00009 の「既存行の付加列を毎回 Wikidata の最新値で埋め直す」判断
- Superseded by: none

## Context

月次バッチ(update-wordlists)の PR #36 で、追記ではなく**既存行の劣化**が多数含まれていることが AI レビューで検出された。

- `sekitsui.csv`: 「ガストロ」の `class` が 魚類 → `NA`、「ユネスコケラトプス」の `extinct` が `yes` → `no`
- `plant.csv`: 「ハゼラン」「ユーカリ」の `class` が 双子葉 → `NA`。あわせて植物でない「ヘビトンボ」(昆虫)が追加された
- `scientist.csv`: 既存行の `country` 72セル・`description` 14セル・`birth_year` 4セルが書き換わった。「カール・フォン・リンネ」の生年が 1707 → 1741(息子の生年)になるなど、同名別人の属性が混入した

原因は共通していて、**「毎回の取得結果でその回の値に上書きする」実装**にある。取得側は次の理由で毎回同じ結果にならない。

1. **取りこぼし**: WDQS のタイムアウト回避で綱・目ごとに分割クエリしているため、1本失敗・部分応答すると、その配下の名前が丸ごと当回の結果から消える
2. **上流のラベル改名**: Wikidata の日本語ラベルは編集される。実際に「ユーカリ」→「ユーカリノキ」「ハゼラン」→「サンカクハゼラン」の改名が起きており、旧名は当回の結果に現れない(結果として旧行が `NA` に落ち、新名が別行として追加される)
3. **上流の表記揺れ・改稿**: `country` の「ノルウェー」→「ノルウェー王国」、Wikipedia 冒頭文の言い換えなど、内容は同じでも文字列が変わる
4. **同名別人の取り違え**: `update_scientist.py` の照合キーは曖昧さ回避サフィックスを落とすため、「カール・フォン・リンネ」と「カール・フォン・リンネ (子)」が同一キーに衝突する。どちらが勝つかは dict の挿入順まかせで、実行ごとに揺れる

いずれも「良いデータが悪いデータで上書きされる」方向に効く。単語リストは追記中心の資産で、既存行は ADR 00007 / 00009 でも「正として保持する」としていたので、上書き前提の実装はその意図とも食い違っている。加えて実務上、月次 PR が既存行の書き換えで埋まると、本来レビューしたい追記差分が埋もれる。

## Decision

自動更新スクリプト全体の原則として **「既存行の埋まっている値を劣化させない」** を採用する。具体的には次の3点。

1. **上書きは当回の取得結果に実データがある場合だけ**。取得結果が欠損(未取得・NA 相当)のとき、既存の非 NA 値を `NA` / `no` / 空文字に落とさない。`NA` → 実値の改善方向は許可する
2. **一方向にしか動かさない列を明示する**
   - `sekitsui` / `plant` の `extinct`: `no` → `yes` のみ。絶滅シグナル(P141・P31)は取りこぼしやすく、取りこぼしで `yes` → `no` に落とすと情報が失われる
   - `scientist` の `status`: `存命` → `物故` のみ。死没は不可逆な事実なので反映する
3. **`scientist` の既存行は空欄補完のみ**。`field/era/birth_year/nobel/gender/country/status/description` は、既存セルが空または `NA` のときだけ書き込む。属性リフレッシュ(毎回の埋め直し)はやめる

あわせて、劣化の温床になっていた2つの取得側の欠陥を直す。

- **同名別人の決定性**: `update_scientist.py` の照合キー衝突時は、(1) 曖昧さ回避サフィックスの無い記事名を優先、(2) 同順は QID 昇順、で決定的に選ぶ。衝突件数は実行ログに出す
- **界をまたぐ誤リンクのガード**: Wikidata の系統樹(P171)には稀に界をまたぐ誤リンクがあり、昆虫「ヘビトンボ」(Q2481303)が被子植物の目(Ranunculales)の配下として引けてしまう。`update_plant.py` は新規追加候補の taxon について上位タクソン(`P171*`)を引き、動物界 Q729 に到達するものを追加しない。判定を Python 側で行うのは、`?t wdt:P171* wd:Q729` と書くと WDQS が動物界側から降りる走査になりタイムアウトするため

## Consequences

- 月次 PR の差分が「追記」中心になり、レビューコスト(および AI レビューの自動マージゲート)が実質的に機能するようになる
- **トレードオフ: 上流の修正が既存行に自動反映されなくなる**。既存行の誤った `class` / `birth_year` / `country` / `description` は、Wikidata 側が直っても自動では直らない。データ修正は個別の PR で人(またはエージェント)が行う。網羅リストは追記が主目的で、既存行は人手のキュレーションを積んでいるため、この非対称は許容する
- **トレードオフ: 誤って `yes` になった `extinct` は自動では戻らない**。絶滅判定はヒューリスティックで偽陽性より偽陰性が多い想定なので、一方向で運用する
- **ラベル改名は「旧名を残したまま新名を追記する」形になる**。「ユーカリ」と「ユーカリノキ」のような重複は残る。網羅リストとしては両方が別名として使えるので実害は小さいが、気になる場合は個別 PR で整理する
- 動物ガードは「新規追加候補のみ」に効く。既に混入している行は自動では消えない(削除は個別 PR)。また、逆向きの誤リンク(植物が動物界に到達する)があると正しい植物を落とすが、その場合は実行ログの「動物混入として除外」に名前が出るので検出できる
- スクリプトの実行ログに「今回未取得だが既存分類を保持」「空欄補完セル数」「存命→物故」「照合キー衝突」を出し、劣化ではなく改善が起きていることを追えるようにする

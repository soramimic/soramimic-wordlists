# ADR 00002: pokemon.csv のフォーム収録・表記ゆれ・タイプ列・型色カード画像

- Status: accepted
- Date: 2026-07-05 (2026-07-28 に型色カード画像の節を追記)
- Supersedes: none
- Superseded by: none

## Context

pokemon.csv は種(全国図鑑順)のみを収録していたが、「ライチュウ（アローラのすがた）」のようなリージョンフォームも空耳の語彙として使いたい。フォームは呼び方が複数あり(ライチュウ / アローラライチュウ / ライチュウ（アローラのすがた）)、どれを表層・発音として採用するかは利用側で選べるようにしたい。また空耳変換の絞り込み用にポケモンのタイプ(でんき等)も持たせたい。

## Decision

- 列は `id, original, surface, pronunciation, type1, type2` とする。type1/type2 はポケモンのタイプの日本語名(PokéAPI ja-Hrkt)。単タイプは `type2=NA`
- 収録するフォームは、名前として独立して呼ばれるものに限定する
  - 地方のすがた: フォーム名が「アローラ/ガラル/ヒスイ/パルデアのすがた」に完全一致するもの
  - キョダイマックスのすがた
  - メガシンカ(`is_mega`)。フォーム名自体が完結した名前(メガリザードンX 等)なので 1 行のみ
  - フォルム違い・ミノ違い・オスメスのすがた・いちげきのかた等は収録しない(単体で名前として呼ばれない)
- 「〇〇のすがた」系は表記ゆれ 3 行を同一 id で持つ。「すがた抜き」でも「すがた込み」でも使えるようにするため:

  ```csv
  id,original,surface,pronunciation,type1,type2
  25,ライチュウ,ライチュウ,ライチュウ,でんき,NA
  1038,ライチュウ（アローラのすがた）,ライチュウ,ライチュウ,でんき,エスパー
  1038,ライチュウ（アローラのすがた）,アローラライチュウ,アローラライチュウ,でんき,エスパー
  1038,ライチュウ（アローラのすがた）,ライチュウ（アローラのすがた）,ライチュウアローラのすがた,でんき,エスパー
  ```

- **id はポケモン単位で振る。** 種と各フォームは別ポケモン(図鑑上も別)なので別 id、同一フォームの表記ゆれ 3 行は同じポケモンなので同一 id。soramimic の実装(js/soramimic.js、editor の lib/soramimic.js)は使用済み単語の判定を id で行っており、これを維持する前提。ライチュウとアローラライチュウは同じ歌詞に共存でき、同一フォームの表記ゆれ同士は排他になる
- 括弧は公式表記に合わせ全角「（）」。発音は括弧を除いて連結し、かなはソースのまま(「のすがた」はひらがな維持)
- 表記の正規化: 全角英数記号は NFKC で半角へ(ポリゴン2、タイプ:ヌル)。♀♂は surface では表記を残し、pronunciation のみメス/オスに置換(ニドラン♀ → 発音ニドランメス)
- id は種が全国図鑑 No−1(0〜)、フォームは種の後ろから連番。フォームの id は世代追加時に振り直されるため、**永続キーには使わない**
- 同名フォームの重複(パルデアケンタロスの 3 品種等)は 1 つに統合し、タイプは最初のフォームのものを使う

## Consequences

- 種 1025 + フォーム 178(2026-07 時点)が収録され、フォームはタイプ絞り込みでも本体と別のタイプ(アローラライチュウ=でんき/エスパー)として扱える
- 「ライチュウ」という発音の行が種とフォームの両方に存在する(別 id なので両方採用されうる)。気になる場合は利用側で pronunciation の重複を除くこと
- キョダイマックスにも一律で「キョダイマックス+種名」の口語行を生成している。不自然なら SUGATA_FORM_NAMES から除外するだけで消せる
- 新世代・新フォームは `tools/update_pokemon.py` の再実行(年次バッチ、手動実行も可)で自動反映される

## Decision: image 列は「型色カード」にする(2026-07 追記)

他リストと同じく画像を持たせたいが、**ポケモンのキャラクター造形(姿・イラスト・ドット絵)は著作物であり、公式アセットの再配布も二次的な描き起こしも本リポジトリでは行わない。** 一方でタイプの配色は事実情報の可視化にすぎず、権利上の問題がない。そこで、**キャラクターを一切描かず、タイプの配色と文字だけで構成したカード画像(型色カード)** を image として配布する。

- 意匠: 320×200 のSVG。上部にタイプ2色の対角グラデーション(単タイプは単色)、その右下に全国図鑑No、下部に名前とタイプチップ。タイプ配色はコミュニティ慣習の色で、公式のカラーパレットではない
- SVGは自己完結(外部フォント・外部画像を参照しない)。日本語名を含むので `font-family` は sans-serif の汎用指定にとどめ、字形は環境依存とする。文字はテキスト要素のまま保持する(検索・読み上げが効く)
- 1 id につき1枚。同一idの表記ゆれ3行は同じカードを共有する
- 生成は `tools/gen_pokemon_typecards.py`、配布は GitHub Release。他リスト(fictional_scientist 等)と同じ配布方式
- **アセットのキーは id ではなく `original`(名前)にする。ファイル名は `pkm_<sha1(original)の先頭10桁>.svg`**(下記「アセットのキー」参照)
- 1リリースあたりのアセットは1000個が上限なので、ハッシュ先頭バイトで `RELEASE_BUCKETS`(=2)個のリリースへ振り分ける(`pokemon-typecard-v2` / `pokemon-typecard-v2b`)。振り分けも名前で決まるので、枚数が増えても既存カードのリリースは動かない。総枚数が 1000×バケット数に近づいたらバケット数を増やすが、そのときは配置が変わるのでタグを `v3` に上げて全枚数を再アップロードする
- `image`/`image_page` は `original` から機械的に組み立てるため、`tools/update_pokemon.py` の全件再生成でも列が消えない。両者はタグ・URL定義を `gen_pokemon_typecards.py` から import して共有する

### アセットのキーは id ではなく名前にする(2026-07 追記)

当初は `pkm_<id4桁>.svg` にしていたが、フォームの id は新種が追加されると全部ずれる(上記のとおり永続キーではない)。id をキーにすると、**古いURLが404にならず「別のポケモンのカード」を指す**(静かな誤表示)。全枚数を再生成して上書きする運用でカバーしていたが、人が実行し忘れると破綻する。

そこで**ファイル名を名前から決定的に導出する**(`sha1(original)` の先頭10桁)。名前が同じなら常に同じファイル名になるので、id がずれてもURLは正しいカードを指す。名前が変わった場合は別のファイル名になり、未生成なら404になる(誤表示より安全)。10桁(40bit)は1203件では衝突確率が無視できる大きさで、生成時に重複チェックもする。

### 図鑑番号は「その名前が指す種の全国図鑑No」にする(2026-07 追記)

当初はカード右下に `id+1` を表示していたが、フォーム(id≥種数)では「1039」のような**実在しない図鑑番号**になっていた(アローラライチュウの正しい番号は026)。フォームには**元の種の図鑑No**を表示する(番号を消すより情報量が多く、公式媒体の表示にも合う)。種は名前から引く:

- 「ライチュウ（アローラのすがた）」→ 括弧の前の「ライチュウ」
- 「メガリザードンX」→ 「メガ」を外し、末尾のX/Y等も落として「リザードン」

引けなければ番号を出さない(実在しない番号を出さない側に倒す)。種とフォームの境目は「フォームとして解決できない行の最大id+1」から求めるので、種数を定数で持たずに済む。

## Consequences (型色カード)

- キャラクターの見分けはつかない。空耳のカード表示で「タイプの雰囲気と名前」を出す用途に限る
- **新ポケモンが追加された回は `tools/gen_pokemon_typecards.py` を再実行して Release を更新する**(アセットが無い名前は画像が404になる)。ただしファイル名が名前由来なので**増えた分だけ送ればよく**(`--upload --only-missing`)、既存カードの作り直しは不要。新種追加でidがずれても既存のURLが別のポケモンを指すことはない
- 取りこぼしは `gen_pokemon_typecards.py --verify` が検出する(CSVの全 original に対応するアセットがReleaseにあるか照合する)。手動メンテの定数(旧 `ASSET_MAX_ID`)は不要になった
- 旧リリース `pokemon-typecard-v1` / `-v1b`(id連番のファイル名)は CSV から参照されなくなったが、外部の参照が切れないよう削除せず残す

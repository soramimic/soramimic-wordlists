# ADR 00022: 減量版カードの職業アイコンに Material Symbols を採る

- Status: proposed
- Date: 2026-07-29
- Supersedes: none
- Superseded by: none
- Related: 00020(選手カード。減量版はその派生で、カードの仕組みを流用する) / 00018(象徴カード。「素材を一切借りない」方針の出どころ) / 00002(型色カード。同じ方針の前例)

`--style minimal` は試作段階で、生成物はまだリポジトリに入っていない。
**この決定は minimal を採用するときに初めて効く。**

## Context

減量版カード(`--style minimal`, ADR 00020 の派生)は、動画レイアウト側が
名前と所属をテキストで描くため、カード内の同じ文字を落とした版である。
文字で書いていた区分(サッカー選手/監督/クラブマスコット/プロ野球選手/
YouTuber/VTuber)が消えるので、代わりに**職業を表す図形**をカードの地紋
(ウォーターマーク)として敷いて6役割を見分けさせる。

ADR 00018 / 00020 では「素材を一切借りず、配色と文字と**自作の図形**だけで
描く」方針を採ってきた。実在のロゴ・エンブレム・マスコットの著作権と、
本人の肖像・キャラクターデザインを避けるための方針である。

この方針に従って6役割ぶんの人型ピクトグラムを自作した(`tools/silhouettes.py`
の旧版。円と多角形と太い帯で組んだ塗り面の図)。**方向性は良かったが造形が
破綻していた**:

- 監督の「翻るコート」が台形のスカートに見え、人物の性別を誤って示唆する
- マスコットの頭・耳・胴が1つの塊に溶けて熊のぬいぐるみの粗い塊になる
- 打者のバットと腕が同じ太さの帯なので、どこからが道具か読めない
- YouTuber のカメラが手から離れた宙に浮く四角になる
- VTuber のヘッドバンドが頭の円と融合して大きな髪の塊に見える

いずれも「何の図かは辛うじて読めるが、下手」に見える。カードは1万3千枚超に
敷くものなので、この品質で固定するのは避けたい。

## Decision

**職業アイコンは Material Symbols(Google, Apache License 2.0)を使う。**
自作にこだわるのをやめ、造形の質はプロの手による素材に任せる。

- 出典: https://github.com/google/material-design-icons
  `symbols/web/<name>/materialsymbolsrounded/<name>_wght700fill1_48px.svg`
- Rounded / 塗りつぶし / wght700 で揃える。wght400 だと走る人型だけが細い
  棒線になり、ホイッスルやカメラのような塗りの塊と並べたとき薄く見える。
  地紋として薄く敷くので、面の量が揃っていることを優先する
- 取り込みは `tools/gen_material_icons.py` が行い、`tools/material_icons.py`
  を生成する。**パスデータは1バイトも変えていない**。元の
  `viewBox="0 -960 960 960"` から、実インクのbboxを測って 0..100 の座標系へ
  収める `transform` を外側に巻いているだけ

### 構成: 人型 + 小さな役割マーク

**人が就く役割は人型を主役にする。** 監督をホイッスル単体、YouTuber を
カメラ単体のような「用具だけ」で表す案も試したが、人の職業を表す絵から人が
消えてしまい、6つ並べたときに「人・物・物・物・物・物」と系統がばらけた。
人型が「人の職業」であることを示し、**小さな役割マーク**が職業を確定させる
構成に改めた。マスコットだけは人ではないので、キャラクターの図そのものを使う。

| 役割 | 役割マーク | ポーズのプール |
| --- | --- | --- |
| サッカー選手 | `sports_soccer`(ボール) | `directions_run` / `sprint` / `sports_martial_arts` / `sports_gymnastics` / `sports_kabaddi` / `directions_walk` / `accessibility_new` |
| サッカー監督 | `sports`(ホイッスル) | `emoji_people` / `accessibility_new` / `accessibility` / `directions_walk` / `hail` / `self_improvement` |
| クラブマスコット | (マークなし) | `smart_toy` / `robot` / `robot_2` / `pets` / `cruelty_free` / `raven` / `pest_control_rodent` / `heart_smile` / `sound_detection_dog_barking` / `sentiment_very_satisfied` |
| プロ野球選手 | `sports_cricket`(バット) | `directions_run` / `sprint` / `accessibility_new` / `accessibility` / `directions_walk` / `sports_gymnastics` / `sports_handball` |
| YouTuber | `videocam`(カメラ) | `emoji_people` / `accessibility_new` / `accessibility` / `directions_walk` / `hail` / `self_improvement` |
| VTuber | `headset_mic`(ヘッドセット) | `self_improvement` / `emoji_people` / `accessibility_new` / `accessibility` / `directions_walk` / `hail` |

選手系は走る・蹴るといった躍動、監督や配信者は立って指示・挨拶をする姿勢と、
**体の使い方でも系統を分けて**いる。マークは手元・腰元・足元の3か所
(サッカー選手は足元・中段・頭の高さ)に置き、どこに置くかも人ごとに変える。
腕を伸ばすポーズでは人型がマークに触れて「持っている」ように見える。

ポーズは**小道具の付いていない全身の人型**に限る。`hiking`(杖)や
`follow_the_signs`(標識)は元から物を持っていて役割マークと情報がぶつかる。
`downhill_skiing` / `surfing` / `roller_skating` のように用具が競技を語る図も、
サッカー選手のカードに敷くとその競技を誤解させる。`person` 系の胸像は全身の
ポーズと並べると別の家族に見え、`man` / `woman` のようなトイレ標識型は加えて
性別を決め打ちしてしまう(女性の YouTuber や監督がいる)。この条件を満たす
図は Material Symbols 全体で10種ほどしかなく、**6〜7種というプールの大きさは
上流の在庫で決まっている**。

マスコットはロボット系だけだと同じ顔が並ぶので、実在のクラブマスコットに
多い動物(うさぎ・鳥・ねずみ・犬)や抽象キャラクター(ハート・スマイル)の図も
混ぜた。Google 製品のマスコットである `android` / `flutter_dash` は、他社の
商標を1万枚のカードに敷くことになるので使わない。

### バリエーション: IDのハッシュで決定的に散らす

同じ区分の人が何十人〜何千人も並ぶので、全員が寸分違わぬ同じ絵だと
「同じ画像を使い回した」ように見える。振り分けは2段構えで、

- **ひと目で違うと分かる軸**: ポーズ(6〜10種) x 役割マークの位置(3か所) x
  左右反転
- **同じ絵に見えるが並べると単調さが消える軸**: ±5度の回転 / ±3の上下
  オフセット / ±10%の拡縮(各5段)

前者だけで1役割あたり **20〜42通り**(サッカー選手32・監督34・野球42・
YouTuber 28・VTuber 34・マスコット20)、後者を掛けると2,500〜5,000通りになる。
マスコットだけ少ないのは役割マークが無く軸が1本足りないためで、
そのぶん母数も88枚と小さい。

選択は**乱数ではなく人物IDのハッシュ**で行う(`silhouettes.variant()`)。
`asset_key()`(名前のsha1)をもう一度ハッシュした整数から、下の桁より
ポーズ・マーク位置・反転・回転・オフセット・拡縮を順に取り出す。乱数にすると
再生成のたびに1万3千枚すべてが差分になってレビューできなくなるため、
**同じ人は何度生成しても必ず同じ図になる**という安定性は必須である。

**ポーズを先に引き、次にそのポーズで使えるマーク位置を引く。**「ポーズと
位置の組」を平らに並べて1つ引くと、位置が3つ残ったポーズが2つしか残らな
かったポーズの1.5倍出てしまう。実データ全件(13,583枚)で確かめてあり、
母数の大きいリストではポーズは均等(サッカー選手・野球とも各13.5〜15.3%)。
マーク位置の側は、ポーズによって使える数が違うぶん 25〜45% と偏る。

振れ幅は `material_icons.py` に定数として書き出し、**その幅で振っても
カードの枠から出ないこと**を生成時に確かめている(`fit_scale` が枠に収まる
縮小率を組ごとに焼き込み、`verify_frame` が振れの端をすべて実際に描いて
bboxを測り直す)。反転・回転・拡縮はどれも組全体に掛かる相似変換なので、
**人型とマークの相対位置は実行時に変わらない**。つまり両者が食い込まない
ことも生成時の1度で確かめれば足りる(`overlap_ratio`。食い込む組は
プールから落とす)。落ちるのは主に「腕を上げたポーズ x 手元のマーク」で、
たとえば `hail` x 手元は輪郭が溶けて何の道具か読めなくなる。

### カード上での見せ方

カード側の仕組み(帯と下地の2色分割・不透明度・入れ子svgでの切り抜き)は
ADR 00020 のものをそのまま使い、**配置だけ変えた**。

自作の人型は縦長で、カード全面に敷いて頭文字ディスク(cx=160, r=48)と
重なっても手足が周りに出るぶん形が読めた。Material のアイコンは正方形に
収まる完結した図なので、中央から右を不透明なディスクに食われると輪郭が
壊れて何の図か読めない。そこで

- アイコンはどれも 0..100 の枠の **右端 x=88 までに収める**
  (`material_icons.LIMIT`。生成時に assert で守る)
- ウォーターマークはカード左半分に敷く(`box=(0, 46, 128)`)。上下は
  46..174 で、帯の境目(y=112)を図のほぼ中央でまたぐ。これ以上大きくすると
  ホイッスルやカメラの役割マークがディスクに掛かって読めなくなる。左端を
  0 に合わせるのは、**左右反転で左に来た役割マークがカードの左辺で削れて
  いた**ため(以前は -3 だった)

## Alternatives

- **自作を続けて造形を直す**: ベジェの制御点を手で詰めれば改善はするが、
  6役割ぶんを「プロの素材と並べて遜色ない」水準に持って行く見込みが立たない。
  1万枚超に敷く図としては割に合わない
- **CC0 / パブリックドメインのアイコンセットを探す**: 帰属義務が無いぶん
  ライセンス面は楽だが、人型アクション(走る・蹴る)まで揃っていて造形が
  一貫しているセットは見つからなかった。Material Symbols は6役割すべてを
  1つの設計言語で賄える
- **アイコンを使わず色と頭文字だけで区別する**: 同じチームの選手と監督と
  マスコットが同じ配色になるため、区別が付かない。減量版の前提が崩れる

## Consequences

### ライセンス上の影響(重要)

**この決定は生成カードのライセンス表示を変える。**

現在 README は `images/baseball/` `images/football/` `images/youtuber/` の
生成カードを **CC0** として案内している。これは現行の `--style full` の
カードが自作の図形と文字だけでできているから成り立っている。

減量版を採用してカードに Material Symbols のパスを埋め込むと、生成カードは
Apache License 2.0 の素材を含む二次的著作物になり、**もはや単純な CC0 では
配布できない**。下流の利用者にも Apache 2.0 の帰属義務が及ぶ。

そのため:

1. `LICENSE-APACHE-2.0-material-symbols` に Apache License 2.0 の全文を置く
2. README の「利用上の注意」に帰属を明記する
3. 生成カードSVGの `<desc>` に1行の帰属を入れる(1枚あたり約80バイト)。
   カードは raw URL で1枚ずつ直リンクされる使われ方をするので、リポジトリの
   LICENSE/README だけでは出所が辿れない
4. **minimal を実際に採用する時点で、README のカード画像の「CC0」の記述を
   改める**(この ADR の時点ではまだ full のみを生成しているので CC0 のまま)

### 方針への影響

- ADR 00018 / 00020 の「素材を一切借りない」方針を、**「実在のロゴ・
  エンブレム・マスコット・肖像・キャラクターデザインは借りない。汎用の
  オープンライセンス素材は帰属を付けて使ってよい」** に緩める。
  避けたかったのは権利者の識別標識であって、汎用アイコンではない
- `tools/silhouettes.py` から自作の作図ヘルパ(`_bar` / `_chain` / `_disc` /
  `_poly` / `_arc_band` / `_fig`)が不要になったので削除した。配置と描画の
  部分は残っている
